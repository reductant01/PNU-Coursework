## 유형 1. 개념 O/X

> **목표:** 틀리면 안 되는 **개념**부터 잡기. ( O / X )

---

### 1-1
**문제:** SVN은 **중앙집중형**, Git은 **분산형** 저장소 모델이다. ( O / X )

**정답:** **O**

**해설:** SVN은 서버 한 곳이 “진짜” 저장소. Git은 각 PC에 **저장소 전체 복사본** + `push`/`pull`.

---

### 1-2
**문제:** GitHub 없이는 Git을 쓸 수 없다. ( O / X )

**정답:** **X**

**해설:** 로컬만 `init` → `add` → `commit` 가능. GitHub는 **원격 공유**용.

---

### 1-3
**문제:** `git init`은 이미 있는 원격 저장소를 **복사**할 때 쓴다. ( O / X )

**정답:** **X**

**해설:** **복사** = `clone` · **빈 저장소 생성** = `init`.

---

### 1-4
**문제:** `git fetch`는 원격 정보만 받고, `git pull`은 받은 뒤 **merge까지** 한다. ( O / X )

**정답:** **O**

**해설:** `pull` ≈ `fetch` + `merge`.

---

### 1-5
**문제:** `git diff`는 **add 전** 작업 폴더 변경, `git diff --cached`는 **add 후** 스테이징 변경을 본다. ( O / X )

**정답:** **O**

**해설:** add 전 → `diff` O · add 후 → `--cached` O.

---

### 1-6
**문제:** `git reset HEAD -- file`은 **unstage**(스테이징 취소), `git checkout -- file`은 **작업 폴더 수정 폐기**다. ( O / X )

**정답:** **O**

**해설:** reset = 커밋 전 스테이징만 취소 · checkout `--` = 마지막 commit 상태로 되돌림(위험).

---

### 1-7
**문제:** `git status -s`에서 **1열 M** = staged, **2열 M** = working tree만 수정. ( O / X )

**정답:** **O**

**해설:** `M  file` = add 함 · ` M file` = add 안 함.

---

### 1-8
**문제:** 원격 반영 순서는 **push → pull → commit** 이 안전하다. ( O / X )

**정답:** **X**

**해설:** **commit → pull → push** (PDF Good practice).

---

### 1-9
**문제:** `git branch 이름`만 실행하면 **그 브랜치로 자동 이동**한다. ( O / X )

**정답:** **X**

**해설:** `branch` = **만들기만** · 이동 = `checkout`(또는 `switch`).

---

### 1-10
**문제:** Git clone/checkout은 **저장소 전체 + 히스토리**를 로컬에 가져온다. ( O / X )

**정답:** **O**

**해설:** SVN 중앙 서버와 달리, 로컬에서 `log`·`commit`·`branch` 등 **네트워크 없이** 가능.

---

### 1-11
**문제:** Git은 파일을 **매 commit마다 스냅샷(snapshot)** 으로 저장한다. ( O / X )

**정답:** **O**

**해설:** PDF "Git takes snapshots". 변경분 diff가 아니라 **그 시점 전체 스냅샷** 개념.

---

### 1-12
**문제:** **Staging area**(스테이징)는 **index**(인덱스)라고도 부른다. ( O / X )

**정답:** **O**

**해설:** PDF slide "A Local Git project has three areas". working directory · **staging area(index)** · Git directory.

## 유형 2. 명령·옵션 빈칸

> **「이런 일을 할 때 빈칸에 뭐?」**

---

### 2-1
**상황:** 모든 Git 프로젝트에 커밋 작성자 이름 `"홍길동"` 저장.

```bash
git config ______ user.name "홍길동"
```

**정답:** `--global`

**해설:** `--global` = 전역. 한 repo만 = `--global` 없이.

---

### 2-2
**상황:** 전역 커밋 **이메일** 설정.

```bash
git config --global user.______
```

**정답:** `email`

**해설:** `user.name`과 함께 commit 메타데이터.

---

### 2-3
**상황:** Git 설정 **목록** 확인 (`history 6.sh`).

```bash
git config ______
```

**정답:** `--list`

---

### 2-4
**상황:** 이 폴더를 **새 Git 저장소**로 (` .git` 생성).

```bash
git ______
```

**정답:** `init`

---

### 2-5
**상황:** 현재 폴더 **모든 파일** 스테이징.

```bash
git add ______
```

**정답:** `.` (현재 디렉터리 전체)

---

### 2-6
**상황:** 메시지 `"Initial commit"`을 **명령줄에서** commit.

```bash
git commit ______ "Initial commit"
```

**정답:** `-m`

---

### 2-7
**상황:** GitHub 저장소를 **내 PC로 복사**.

```bash
git ______ https://github.com/user/repo.git
```

**정답:** `clone`

---

### 2-8
**상황:** diff 종류 선택.

| 보고 싶은 것 | 명령 |
|--------------|------|
| `add` **안 한** 변경 | `git ______` |
| `add` **한** 변경 | `git diff ______` |

**정답:** `diff` / `--cached`

---

### 2-9
**상황:** **unstage** (수정 내용은 유지).

```bash
git reset HEAD ______ readme.txt
```

**정답:** `--`

---

### 2-10
**상황:** 작업 폴더 **수정 폐기** (마지막 commit으로).

```bash
git checkout ______ readme.txt
```

**정답:** `--`

---

### 2-11
**상황:** log **한 줄 요약** (`history 6.sh`).

```bash
git log ______
```

**정답:** `--oneline`

---

### 2-12
**상황:** log **최근 5개만**.

```bash
git log ______
```

**정답:** `-5`

---

### 2-13
**상황:** 원격 `master` **가져와 merge**.

```bash
git pull ______ ______
```

**정답:** `origin` `master` (또는 `main`)

**해설:** `origin` = 원격 **별칭** · `master`/`main` = **브랜치 이름**.

---

### 2-14
**상황:** 로컬 commit을 원격에 **올림**.

```bash
git push ______ ______
```

**정답:** `origin` `master` (또는 `main`)

---

### 2-15
**상황:** 브랜치 이름을 `main`으로 **강제** 변경 (`history 6.sh`).

```bash
git branch ______ main
```

**정답:** `-M`

**해설:** `-m` = move · `-M` = **force** move.

---

### 2-16
**상황:** 첫 push 시 upstream 설정.

```bash
git push ______ origin main
```

**정답:** `-u`

**해설:** `-u` = `--set-upstream` · 이후 `git push`만으로 가능.

---

### 2-17
**상황:** 원격 정보만 받기 (**merge 안 함**).

```bash
git ______
```

**정답:** `fetch`

---

### 2-18 (명령 ↔ 역할)
**문제:** 빈칸에 **역할 한 줄**을 쓰시오.

| 명령 | 역할 (빈칸) |
|------|-------------|
| `git clone` | ______ |
| `git add` | ______ |
| `git commit` | ______ |
| `git status` | ______ |
| `git pull` | ______ |
| `git push` | ______ |

**정답:** 저장소 **복사** / **스테이징**에 추가 / 스냅샷 **영구 저장** / working·staging **상태 확인** / 가져와 **병합**(fetch+merge) / 원격에 **반영**

---

### 2-19
**상황:** `commit` 명령 **도움말**을 본다. (PDF: `git help [command]`)

```bash
git ______ commit
```

**정답:** `help`

**해설:** `git help commit` = `git commit --help` 와 같음. PDF "get help info about a particular command".

## 유형 3. 명령줄·설정 빈칸 (여러 줄)

> **소스·워크플로 조각** 빈칸 (공지: source codes)

---

### 3-1
**상황:** `experimental` 브랜치 만들고 → 이동 → `master`로 → merge.

```bash
git ______ experimental
git ______ experimental
git ______ master
git ______ experimental
```

**정답:** `branch` / `checkout` / `checkout` / `merge`

**해설:** 만들기 / 이동 / 이동 / **현재 브랜치에** 합치기.

---

### 3-2 (history 6.sh)
**상황:** 새 repo를 GitHub에 **처음** 올림.

```bash
git init

git remote add origin <URL>

```

**정답:** `-M` / `-u`

**해설:** 브랜치 이름 확정 후 push + upstream.

---

### 3-3
**상황:** 전역 user.name·email **한 번에** 설정할 때 쓰는 config 키 두 개.

```bash
git config --global user.______
git config --global user.______
```

**정답:** `name` / `email`

## 유형 4. 순서·로직 빈칸

> **알고리즘·워크플로 순서** (공지: coding algorithms)

---

### 4-1
**문제:** Git **기본 3단계** (수정 → ? → ?) 순서.

**정답:** ① 파일 수정 → ② `git add` → ③ `git commit`

---

### 4-2
**문제:** 로컬 Git **세 영역** 순서 (영문).

**정답:** ① Working directory ② Staging area ③ Git directory (`.git`)

---

### 4-3
**문제:** 원격 반영 **안전한 3단계** 순서.

**정답:** ① add & **commit** ② **`git pull`** ③ **`git push`**

---

### 4-4 (history 6.sh)
**문제:** 아래에 **번호** (1~6).

```
( ) git push -u origin main
( ) git init
( ) git add .
( ) git commit -m "first commit"
( ) git branch -M main
( ) git remote add origin <URL>
```

**정답:** 1.init · 2.add . · 3.commit · 4.branch -M main · 5.remote add · 6.push -u

---

### 4-5
**문제:** 커밋 고유 ID(40자 16진) 이름은?

**정답:** **SHA-1 hash** (체크섬, commit ID)

**해설:** `git log --oneline`의 `1677b2d` = 앞 7자.

## 유형 5. 상태·메시지 예측

> **`git status` / `-s` 표기** (공지: command outcomes)

---

### 5-1
**상황:** `rea.txt` 수정만, **`add` 안 함**.

**문제:** `git status -s`에서 `M`은 **몇 번째 열**?

**정답:** **2번째 열** (` M rea.txt`)

---

### 5-2
**상황:** 5-1 다음 **`git add rea.txt`**, commit 전.

**문제:** `M`은 **몇 번째 열**?

**정답:** **1번째 열** (`M  rea.txt`)

---

### 5-3
**상황:** 추적 안 된 새 파일 `foo.txt`만 있음.

**문제:** `git status -s` 출력 한 줄?

**정답:** `?? foo.txt`

**해설:** `??` = **untracked**.

---

### 5-4
**상황:** `git add` 후 **새 파일** 스테이징.

**문제:** `git status -s` 1열 표기는?

**정답:** **`A`** (예: `A  foo.txt`)

---

### 5-5
**상황:** `git status` 출력: `Your branch is ahead of 'origin/main' by 2 commits.`

**문제:** (1) 의미 한 줄 (2) 보통 다음에 할 명령?

**정답:** (1) 로컬에 원격보다 **2 commit 앞섬** (push 안 함) (2) **`git push`**

---

### 5-6
**상황:** `git status` 출력: `Your branch is behind 'origin/main' by 2 commits.`

**문제:** (1) 의미 (2) 보통 다음 명령?

**정답:** (1) 원격이 로컬보다 **2 commit 앞섬** (2) **`git pull`**

## 유형 6. diff·log 출력 예측

> **명령 실행 시 diff/log 결과** (공지: outcomes)

---

### 6-1
**상황:** `rea.txt` 수정만, **`add` 안 함**.

**문제:** `git diff` / `git diff --cached` — 출력 **있음/없음**?

**정답:** `git diff` **있음** / `--cached` **없음**

---

### 6-2
**상황:** 수정 후 **`git add rea.txt`**, commit 전.

**문제:** `git diff` / `git diff --cached`?

**정답:** `git diff` **없음** / `--cached` **있음**

---

### 6-3
**상황:** `README.md` 수정, **`add` 안 함**.

**문제:** 아래 중 출력 **있는** 것? (모두 고르기)

- `git diff`
- `git diff --cached`
- `git diff HEAD`

**정답:** `git diff` · `git diff HEAD` · `--cached`는 **없음**

**해설:** unstaged 변경 → `diff`·`HEAD` O · staged 없음 → `--cached` X.

---

### 6-4
**상황:** commit **3개** 존재.

**문제:** (1) `git log` (2) `git log --oneline` — **줄 수** 차이?

**정답:** (1) commit당 **여러 줄** (hash·author·날짜·메시지) (2) **3줄** (한 줄에 hash+메시지)

---

### 6-5 (종합 표)
**상황:** `rea.txt` 한 파일만 다룸.

**문제:** 단계별로 `status -s` / `git diff` / `--cached` 를 O/X로 채우시오.

| 단계 | status -s | git diff | git diff --cached |
|------|-----------|----------|-------------------|
| 수정만 | 2열 M | O | X |
| add 후 | 1열 M | X | O |

**정답:** 위 표 그대로

**해설:** 유형 5-1~5-2 + 6-1~6-2 종합. 시험 **표 채우기** 형태 대비.
