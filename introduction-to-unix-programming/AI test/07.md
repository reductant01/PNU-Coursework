## 유형 1. 개념 O/X

> **목표:** 틀리면 안 되는 **개념**부터 잡기. ( O / X )

---

### 1-1
**문제:** Linux에 **로그인**할 때 bash가 읽는 설정 파일들을 **startup files**(시작 파일)라고 한다. ( O / X )

**정답:** **O**

**해설:** PDF slide 2~3. startup file = 쉘이 시작될 때 명령을 실행하는 설정 파일.

---

### 1-2
**문제:** `/etc/profile`은 **시스템 전체** 사용자에게 공통으로 적용된다. ( O / X )

**정답:** **O**

**해설:** PDF slide 4~5. 로그인 시 **모든 사용자**가 같이 쓰는 startup 파일. `export PATH USER ...` 등 환경 변수 설정.

---

### 1-3
**문제:** `~/.bash_profile`, `~/.bash_login`, `~/.profile` 은 **사용자마다** 다르게 설정할 수 있다. ( O / X )

**정답:** **O**

**해설:** `~`(`$HOME`) 아래 **개인** startup. 배포판은 보통 **하나만** 씀 — 없으면 **1st** `.bash_profile` → **2nd** `.bash_login` → **3rd** `.profile` 순으로 시도.

---

### 1-4
**문제:** 터미널에 `bash`만 입력해 시작한 **interactive shell**도 `/etc/profile`을 처리한다. ( O / X )

**정답:** **X**

**해설:** **Login shell** = SSH·GUI 터미널 **첫 로그인** → `/etc/profile` + `.bash_profile` 등. **Interactive shell** = 이미 로그인된 상태에서 `bash`만 쳐서 **또 하나** 띄운 쉘 → `/etc/profile` **안 읽음**(시스템 초기화는 로그인 시 한 번). 대신 **`~/.bashrc`** 확인 (`history 2.sh`).

---

### 1-5
**문제:** Interactive shell은 사용자 홈의 **`.bashrc`** 를 확인한다. ( O / X )

**정답:** **O**

**해설:** PDF slide 9~10. alias·개인 설정은 보통 `.bashrc`. `history 2.sh`의 `~/.bashrc`·`source`도 이 파일.

---

### 1-6
**문제:** Login shell과 interactive shell은 **같은** startup 파일만 읽는다. ( O / X )

**정답:** **X**

**해설:** login = `/etc/profile` + `.bash_profile` 등 · interactive = **`.bashrc`만**(로그인용 파일 안 읽음).

---

### 1-7
**문제:** `/etc/profile`은 `profile.d` 폴더 안의 `.sh` 파일들을 **불러올 수 있다**. ( O / X )

**정답:** **O**

**해설:** `for i in /etc/profile.d/*.sh; do . "$i"; done` — `.`(source)로 `lang.sh` 등 **조각 설정** 실행.

---

### 1-8
**문제:** 내가 만든 **alias**(예: `ll='ls -l'`)는 **주로 `/etc/profile`에만** 저장하고, `~/.bashrc`는 쓰지 않는다. ( O / X )

**정답:** **X**

**해설:** alias는 **개인** 설정 → **`~/.bashrc`**. `/etc/profile`은 **전체 사용자 공통**이라 내 alias 넣기엔 맞지 않음.

---

### 1-9
**문제:** `mytest=(one two three)` 에서 괄호 `( )` 로 여러 값을 넣는 것을 **배열(array)** 이라고 한다. ( O / X )

**정답:** **O**

**해설:** PDF slide 13. `이름=(값1 값2 값3)` — 공백으로 구분.

---

### 1-10
**문제:** bash 배열에서 `echo $mytest`(인덱스 없음)는 **첫 번째 요소만** 출력한다. ( O / X )

**정답:** **O**

**해설:** `$mytest` ≡ `${mytest[0]}`. 전체는 `${mytest[*]}`. 인덱스는 **0부터** — 세 번째 = `[2]`.

---

### 1-11
**문제:** `alias`는 **그 쉘 안**에서만 유효하고, `bash`로 자식 쉘을 만들면 alias가 **자동으로** 넘어간다. ( O / X )

**정답:** **X**

**해설:** PDF slide 15 · `history 6.sh` 8행. alias는 **지역**과 비슷 — 자식 `bash`에서 `li` → `command not found`. `export` 환경 변수와 **다름** (`06.md`).

---

### 1-12
**문제:** `source ~/.bashrc` 와 `. ~/.bashrc` 는 같은 효과이다. ( O / X )

**정답:** **O**

**해설:** `history 2.sh` 19행 — 둘 다 설정 파일을 **현재 쉘**에 반영. `. file` ≠ `./script.sh`(후자는 **자식** 프로세스 실행).

---

### 1-13
**문제:** `export` 없이 `.bashrc`에 넣은 alias도 **그 쉘 세션**에서는 동작한다. ( O / X )

**정답:** **O**

**해설:** `.bashrc`를 **source**하면 그 세션에서 alias 동작. alias는 export 대상이 아님.

---

### 1-14
**문제:** 이미 로그인된 터미널에서 `bash`만 입력해 띄운 쉘은 **login shell**이다. ( O / X )

**정답:** **X**

**해설:** SSH·GUI **첫 로그인** = **login shell** → `/etc/profile` + `~/.bash_profile` 등 (`1-4` `5-3` **가**). `bash`만 입력 = **interactive shell**(로그인 아님) → **`~/.bashrc`만** · `/etc/profile` **안 읽음**.

---

### 1-15
**문제:** `alias`는 `export`한 환경 변수와 같이 자식 `bash`에 자동 전달된다. ( O / X )

**정답:** **X**

**해설:** PDF slide 15 — alias는 **지역적**. 단, 자식 **대화형** 쉘은 **자기 startup으로 `~/.bashrc`를 다시 읽음** → 파일에 저장된 alias는 자식에서 **다시** 정의됨(유형 5 참고).

---

## 유형 2. 명령·옵션 빈칸

> **「이런 일을 할 때 빈칸에 뭐?」**

---

### 2-1
**상황:** `~/.bashrc`에 `PATH`를 수정해 넣었다. **로그아웃 없이** 현재 쉘에 바로 반영한다. (`history 2.sh`)

```bash
______ ~/.bashrc
```

**정답:** `source` (또는 `.`)

**해설:** `source` = **현재 쉘**에서 파일 내용을 **다시 읽어 실행**. `source ~/.bashrc` = **지금 쉘**만 반영 · 로그인 = startup **자동**.

---

### 2-2
**상황:** 홈 아래 `bin`에 실행 파일을 두고 이름만으로 실행하고 싶다. (PDF `.bash_profile` 패턴)

```bash
PATH=$PATH:$______/bin
export PATH
```

**정답:** `HOME` (또는 `~` → `$HOME`)

**해설:** PDF slide 8. 기존 `PATH` **유지** + 홈의 `bin` **추가**. `06.md` 2-7과 같은 append 패턴.

---

### 2-3
**상황:** `/etc/profile`이 `profile.d` 안 스크립트를 불러온다.

```bash
for i in /etc/profile.d/*.sh; do
    ______ "$i"
done
```

**정답:** `.` (또는 `source`)

**해설:** PDF slide 4~6. `. $i` = `$i` 파일을 **현재 쉘에서 실행** — `LANG` 등 설정.

---

### 2-4
**상황:** 변수 `colors`에 red green blue 세 값을 넣는다.

```bash
colors=(______ green ______)
```

**정답:** `red` / `blue` → `colors=(red green blue)`

**해설:** PDF slide 13. 공백으로 구분, 괄호 필수.

---

### 2-5
**상황:** `mytest=(one two three four five)` — **세 번째** 값만 출력. (인덱스 0부터)

```bash
echo ${mytest[______]}
```

**정답:** `2`

**해설:** 0=`one`, 1=`two`, 2=`three`. `${mytest[*]}` = 전체.

---

### 2-6
**상황:** `ls -il` 을 `li` 한 글자로 쓰고 싶다. (`history 6.sh`·PDF)

```bash
______ li='ls -il'
```

**정답:** `alias`

**해설:** PDF slide 15 · `history 6.sh` 8행. `alias 이름='명령'` 형식.

---

### 2-7
**상황:** 시스템에 등록된 alias를 **목록**으로 본다.

```bash
alias ______
```

**정답:** `-p`

**해설:** PDF slide 14. **`-p`** = **p**rint — 등록된 alias를 `alias 이름='명령'` **재사용 가능 형식**으로 **출력** (`6-6`).

---

### 2-8
**상황:** 로그인 시 `.bash_profile`이 `.bashrc`를 먼저 불러온다.

```bash
if [ -f ~/.bashrc ]; then
    ______ ~/.bashrc
fi
```

**정답:** `.` (또는 `source`)

**해설:** PDF slide 8. login shell은 `.bashrc`를 **자동으로 안 읽을 수** 있음 — `.bash_profile`이 **source**하는 구조.

---

### 2-9
**상황:** alias `li`를 **제거**한다.

```bash
______ li
```

**정답:** `unalias`

**해설:** `alias`로 만든 별칭 삭제. 자식 쉘에는 원래 안 넘어감.

---

### 2-10 (명령 ↔ 역할)
**문제:** 빈칸에 **역할 한 줄**을 쓰시오.

| 명령·문법 | 역할 (빈칸) |
|-----------|-------------|

| `alias -p` | ______ |
| `arr=(a b c)` | ______ |
| `${arr[2]}` | ______ |
| `${arr[*]}` | ______ |

**정답:** 설정 파일을 **현재 쉘**에 반영 / 명령 **별칭** 등록 / 등록된 alias **목록** 출력 / 변수 **배열** 선언 / 인덱스 2번 **요소** 접근 / 배열 **전체** 요소 나열

**해설:** `history 2.sh`의 `source`·`history 6.sh`의 `alias`와 PDF Part2 핵심 명령 정리. **`alias -p`** 의 **`-p`** = **p**rint (`2-7` `6-6`).

## 유형 3. 명령줄·설정 빈칸 (여러 줄)

### 3-1

if [ -f ~/.bashrc ]; then

### 3-2
**상황:** `history 2.sh` — `~/.bashrc`에 `PATH`와 alias 추가.

**정답:** `mybin` (또는 임의 경로명) / `alias`

**해설:** `history 2.sh` 17~18행. 파일만 고치면 **현재 쉘**은 모름 → **`source`** 로 즉시 반영(유형 4-1).

        ______ "$i"
    fi

```

**정답:** `.` (또는 `source`)

**해설:** PDF slide 4~6. `/etc/profile` = **전체 사용자**, `export`, `profile.d` + `.`

---

### 3-4
**상황:** 배열 값 **일부 변경** 후 전체 출력. (PDF slide 13)

```

**정답:** `yellow` (또는 임의 값) / `[*]`

**해설:** `[1]=yellow`로 **두 번째**만 변경. `[*]` = 전체 나열.

### 3-5

## 유형 4. 순서·로직 빈칸

> **알고리즘·워크플로 순서** (공지: coding algorithms)

---

### 4-1
**문제:** Login shell이 처리하는 파일 **순서**에 번호를 매기시오. (PDF slide 3)

```
( ) $HOME/.bash_profile   [1st Try]
( ) /etc/profile          [Common]
( ) $HOME/.profile        [3rd Try]
( ) $HOME/.bash_login     [2nd Try]
```

**정답:** 1. `/etc/profile` · 2. `~/.bash_profile` · 3. `~/.bash_login` · 4. `~/.profile`

**해설:** **공통** `/etc/profile` 먼저 → 사용자 파일은 **하나만** 성공하면 됨: **1순위** `.bash_profile` → **2순위** `.bash_login` → **3순위** `.profile`.

---

### 4-2
**문제:** Login shell startup 처리 — 빈칸에 파일 경로.

```
1) ______          (모든 사용자 공통)
2) $HOME/.bash_profile  (1st Try)
3) $HOME/.bash_login    (2nd Try)
4) $HOME/.profile       (3rd Try)
```

**정답:** `/etc/profile`

**해설:** 2~4는 **사용자 홈** 아래, **하나만** 성공하면 나머지는 건너뛸 수 있음.

---

### 4-3
**상황:** `~/.bashrc`에 `PATH`와 `alias`를 추가했지만 **현재 터미널**에 안 보인다.

**문제:** 아래 단계에 번호를 매기시오.

```
( ) ~/.bashrc 파일을 편집한다 (nano ~/.bashrc)
( ) 터미널에서 source ~/.bashrc (또는 . ~/.bashrc)
( ) echo $PATH / alias 로 확인
( ) 새 로그인 시에는 .bash_profile 이 .bashrc 를 불러올 수 있음
```

**정답:** 1. 편집 · 2. `source` · 3. 확인 · 4. (참고) 로그인 시 자동 로드

**해설:** `history 2.sh` 18~19행. 다음 로그인부터는 startup 파일이 **자동** 실행.

---

### 4-4
**상황:** `~/.bash_profile` **없음**, `~/.bash_login` **있음**, login shell.

**문제:** bash가 읽는 **사용자** startup 파일은?

**정답:** `~/.bash_login`

**해설:** 4-1 순서. 1st Try 실패 → **2nd Try** `.bash_login`.

---

### 4-5
**문제:** Interactive shell startup은 **새 대화형 쉘**이 뜰 때마다 실행된다. ( O / X ) — 그때 읽는 **대표** 사용자 파일은?

**정답:** **O** · **`~/.bashrc`**

**해설:** PDF slide 10~11 — `bash`만 쳐서 뜬 **대화형** 쉘도 startup(`.bashrc`) 실행. `/etc/profile` **안 읽음**.

## 유형 5. 상태·메시지 예측

> **명령 실행 시 메시지·동작** (공지: command outcomes)

---

### 5-1
**상황:** PDF slide 15

```bash
alias li='ls -il'
bash
li
```

**문제:** 자식 쉘에서 `li` 입력 시 어떤 메시지가 나는가?

**정답:** `bash: li: command not found` (또는 **command not found**)

**해설:** **`alias li='ls -il'`** 안의 **`ls` 옵션:**

| 옵션 | 축약 | 의미 |
|------|------|------|
| **`-l`** | **l**ong | **긴 형식** — 권한·소유자·크기·날짜·이름 (`08.md`·`history 2.sh`) |
| **`-i`** | **i**node | 각 파일 **맨 앞**에 **inode 번호**(Linux가 파일을 구분하는 **내부 ID**) 출력 |

**`ls -i` / `ls -il` 출력 예 (개념):**

```bash
ls -i
# 524288 file.txt
# 524301 mydir

ls -il    # = alias li
# 524288 -rw-r--r-- 1 sj sj  100 ... file.txt
# 524301 drwxr-xr-x 2 sj sj 4096 ... mydir
#   ↑ inode          ↑ -l 덕분에 권한·소유자 등
```

**`-i`만:** 이름 앞 **숫자(inode)** · **`-il`:** 그 숫자 **+** `-l` 긴 목록.

**자식 쉘에서 `command not found`:** 부모에서 **명령줄로만** `alias li=...` 친 경우 → **자식 `bash`에 alias 없음** · `~/.bashrc`에 있으면 자식이 **rc를 다시 읽을 때**는 `li` **동작** (5-4 참고). 이 문제(PDF slide 15)는 **명령줄 alias만** → **X**.

**상황:** `~/.bashrc`에 `alias hi='echo hello'` 추가만 해 둠. **아직 `source` 안 함.**

**문제:** (1) `source` 전 `hi` 입력 (2) `source ~/.bashrc` 후 `hi` 입력 — 결과?

**정답:** (1) `command not found` (2) `hello` 출력

**해설:** 파일만 수정 ≠ 현재 쉘 반영. `source` = **지금 쉘**에 적용 (`history 2.sh`).

### 5-3
**상황:** (가) SSH로 로그인했다. (나) 이미 로그인된 터미널에서 `bash`만 입력했다.

**문제:** (가)(나) 각각 **먼저** 읽는 대표 startup 파일은?

**정답:**  
(가) **`/etc/profile`** (+ 이어서 `~/.bash_profile` 등)  
(나) **`~/.bashrc`** (`/etc/profile` **아님**)

**해설 — 쉘 종류와 startup (`1-4` `1-6` `4-1` · PDF slide 3 vs 9):**

| 구분 | 언제? | 쉘 종류 | **먼저** 읽는 대표 파일 |
|------|-------|---------|-------------------------|
| **(가) SSH 로그인** | 계정 **처음** 들어올 때 | **login shell** | **`/etc/profile`** (전체 공통) |
| **(가) 이어서** | (가) 직후 | login shell | **`~/.bash_profile`** 등 (개인 · 없으면 `.bash_login` → `.profile`) |
| **(나) `bash`만 입력** | 이미 로그인된 터미널에서 **또 하나** 띄움 | **interactive shell** (로그인 **아님**) | **`~/.bashrc`만** |

**왜 (나)는 `/etc/profile` 을 안 읽나?**

- `/etc/profile` = **로그인할 때 한 번** 하는 **시스템·전체 사용자** 초기화.
- (나)는 **이미 로그인된 세션** 안에서 쉘만 하나 더 띄운 것 → **그 초기화를 다시 안 함**.
- 대신 **개인 설정·alias**용 **`~/.bashrc`** 만 읽음 (`1-5` `history 2.sh`).

**읽는 순서 한눈에:**

```
(가) login:    /etc/profile  →  ~/.bash_profile  →  (있으면) source ~/.bashrc
(나) interactive:              ~/.bashrc 만
```

**헷갈리기 쉬운 점 (`1-14`):** `bash`만 친 것 = **interactive** · **login shell 아님** → (나) 정답.

---

### 5-4
**상황:** `history 2.sh` + PDF — `~/.bashrc`에 아래 내용 **저장**됨.

```bash
PATH=$PATH:$HOME/mybin
alias mk='mkdir'
```

부모 쉘에서 `source ~/.bashrc` 실행 **후** `bash`로 **자식 대화형 쉘** 진입.

**문제:**  
(1) `source` **전** `mybin`이 `PATH`에 없으면 `myprog` 실행 시 오류 키워드는?  
(2) `source` **후** 부모 쉘에 반영되는 이유는?  
(3) 자식에서 `mk test` 동작하는가? (O/X)  
(4) 반대로, 부모에서 **명령 줄로만** `alias mk='mkdir'` 입력(**`~/.bashrc`에는 없음**) 후 `bash` 진입. 자식에서 `mk` 동작하는가? (O/X)

**정답:**  
(1) **command not found**  
(2) `source` / `.` 가 `~/.bashrc`를 **현재(부모) 쉘**에서 다시 읽어 `PATH`·alias를 **즉시 적용**  
(3) **O**  
(4) **X**

**해설:** (3) **O** — 부모에서 alias가 **넘어가는(상속)** 게 아니라, 자식 `bash`는 **대화형 interactive shell**이라 **자기 startup으로 `~/.bashrc`를 다시 읽음** → 파일에 있는 `alias mk`가 **자식 안에서 다시** 정의됨. (4) **X** — bashrc **파일에 없고** 부모에서만 친 alias는 자식에 **없음**. **`. ~/.bashrc`** = **부모**에 적용 · 자식은 **별도로 rc 읽기**(파일에 있으면 (3)처럼 **O**).

### 5-5
**문제:** login shell에서 `.bashrc`의 alias가 적용되려면 보통 `.bash_profile`이 무엇을 해야 하는가?

**정답:** `. ~/.bashrc` (또는 `source ~/.bashrc`)로 **불러와야** 함

**해설:** login shell은 `.bashrc`를 **자동으로 안 읽을 수** 있음 — `.bash_profile`이 **source**하는 구조(3-1).

## 유형 6. diff·log 출력 예측

---

### 6-1
**상황:**

```bash
mytest=(one two three four five)
echo ${mytest[0]}
echo ${mytest[1]}
echo ${mytest[*]}
```

**문제:** 출력 3줄을 순서대로?

**정답:**

```
one
two
one two three four five
```

**해설:** PDF slide 13. `[0]`·`[1]` = 첫·두 번째. `[*]` = **전체** 요소(공백 구분). `$arr` vs `${arr[*]}`: `$arr` = **첫 요소만**.

---

### 6-2
**상황:**

```bash
mytest=(one two three four five)
unset mytest[2]
echo ${mytest[*]}
```

**문제:** 출력은?

**정답:** `one two four five` (`three`만 빠짐)

**해설:** `unset mytest[2]` = 인덱스 2(**three**)만 삭제. 나머지 인덱스 번호는 유지.

---

### 6-3
**상황:** `arr=(alpha beta gamma)`

**문제:** `echo $arr` 와 `echo ${arr[1]}` 출력은?

**정답:** `alpha` / `beta`

**해설:** `$arr` = 인덱스 생략 시 **첫 요소만** (`$arr` ≡ `${arr[0]}`). `[1]` = 두 번째.

---

### 6-4
**상황:** PDF slide 13

```bash
colors=(red green blue)
echo $colors
echo ${colors[2]}
colors[1]=yellow
echo ${colors[*]}
```

**문제:**  
(1) 첫 `echo $colors` 출력?  
(2) `echo ${colors[2]}` 출력?  
(3) 마지막 `echo ${colors[*]}` 출력?

**정답:**  
(1) `red`  
(2) `blue`  
(3) `red yellow blue`

**해설:** `[1]=yellow`로 **두 번째**만 변경. `[*]` = 전체 나열. 인덱스 **0부터** — `[2]` = **세 번째** = `blue`.

### 6-5
**상황:** `mytest=(a b c)` 이후 아래 명령.

```bash

```

**문제:** 출력 2줄은?

**정답:** `a` / `c`

**해설:** `$mytest` = **첫 요소만**. `[2]` = 인덱스 2 = **세 번째** 값 `c`.

### 6-6
**상황:** 현재 쉘에 아래 alias만 등록됨.

```bash
alias li='ls -il'
alias mk='mkdir'
```

**문제:** `alias -p` 출력에 **반드시 포함**되는 패턴 2가지는? (형식만)

**정답:** `alias li='ls -il'` · `alias mk='mkdir'` (또는 `alias li=…` / `alias mk=…` 형태의 **등록 목록**)

**해설 — `alias -p` (`2-7`):**

| 부분 | 뜻 |
|------|-----|
| **`alias`** | 별칭 **등록**·**조회** |
| **`-p`** | **p**rint — 정의된 alias를 **`alias NAME=VALUE` 형식**으로 **목록 출력** (bash `help alias`) |

```bash
alias li='ls -il'
alias mk='mkdir'
alias -p
# alias li='ls -il'
# alias mk='mkdir'
```

→ **등록된 것만** 나열 · 없는 별칭은 **출력에 없음** · `alias` **인자 없음**도 비슷하게 목록 출력하지만 **`-p` = 명시적으로 print 형식**.
