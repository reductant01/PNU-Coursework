### 1-2
**문제:** 스크립트 **첫 줄** **`#!/bin/bash`** 는 **주석**이 아니라 **어떤 쉘로 실행할지** 알린다. ( O / X )

**정답:** **O**

**해설:** PDF slide 6.

**`#!/bin/bash` = shebang(쉬뱅) — 스크립트 **맨 첫 줄** 전용:**

```
#!/bin/bash
││ └─ /bin/bash  ← 이 **프로그램(쉘)** 으로 아래 줄들을 실행해라
│└── !  ← “이건 특별한 첫 줄이다” 표시
└─── #  ← 보통 주석이지만, **1행 + !** 이면 **주석 아님**
```

| 부분 | 뜻 |
|------|-----|
| **`#!`** | **sh**ebang — “**이 파일을 **어떤 인터프리터**로 실행할지**” 표시 |
| **`/bin/bash`** | **bash 쉘** 실행 파일 **경로** (Linux에서 흔한 위치) |

**왜 필요?** — 파일 **`test1`** 은 **텍스트**일 뿐 · OS는 **bash로 돌릴지 python으로 돌릴지** 모름 → **1행**이 **“bash로 읽어라”** 라고 알려 줌.

**2행부터 `#`:**

```bash
#!/bin/bash          ← shebang (실행)
# This is a comment  ← 진짜 주석 (쉘이 **무시**)
date                 ← 실제 명령
```

**실행:** **`chmod u+x test1`** 후 **`./test1`** — 커널/시스템이 **1행** 보고 **`/bin/bash test1`** 처럼 실행 (1-4).

**다른 예:** `#!/bin/sh` · Python은 `#!/usr/bin/python3` — **같은 shebang 패턴**.

### 1-5
**문제:** **`echo -n "text"`** 는 **줄바꿈 없이** 출력해 **다음 명령 출력과 같은 줄**에 이어 붙일 수 있다. ( O / X )

**정답:** **O**

**해설:** PDF slide 7.

**`echo` 기본:** 출력 **끝에 줄바꿈(Enter)** 이 **자동**으로 붙음 → **다음 출력은 무조건 다음 줄**.

**`echo -n`:** **줄바꿈 안 붙임** → **바로 이어서** 다음 출력 가능.

| 옵션 | 축약 | 뜻 |
|------|------|-----|
| **`-n`** | **n**o newline | 출력 **끝 줄바꿈(Enter) 생략** |

**PDF 예 (test1):**

```bash
echo -n "The time and date are: "
date
```

| | **`-n` 없음** | **`-n` 있음** |
|--|---------------|---------------|
| 화면 | `The time and date are:` ↵ ↵ `Mon Sep 24 …` ( **두 줄** ) | `The time and date are: Mon Sep 24 …` ( **한 줄** ) |

```
-n 없음:
The time and date are:
Mon Sep 24 20:11:35 EST 2007

-n 있음:
The time and date are: Mon Sep 24 20:11:35 EST 2007
```

**정리:** **`-n`** = **n**o newline — “**echo만** 출력하고 **Enter 치지 마**” → **`date`** 결과가 **같은 줄**에 붙음.

### 1-6
**문제:** **`echo "The cost is $15"`** 는 **`$1`** 과 **`5`** 로 해석되어 **`5`** 만 출력될 수 있다. ( O / X )

**정답:** **O**

**해설:** PDF slide 8.

**쉘 규칙:** **`"` 안에서도 `$`** 뒤는 **변수**로 해석됨 · **`$15`** = **`$1`** + **`5`** (15라는 변수 **아님**).

**왜 `$15`가 “15달러”가 아닌가?**

```
$15  →  $1  +  5
        │      └── 남는 글자 (숫자 5)
        └── **1번째 인자** 변수 ($1, $2, … $9 까지 이름 규칙)
```

| 표현 | 쉘이 읽는 뜻 |
|------|--------------|
| **`$1`** | 스크립트 **첫 번째 인자** |
| **`$15`** | **`$1`** 값 + 글자 **`5`** ( **`$15`라는 변수 없음** ) |
| **`${15}`** | (참고) **15번째 인자** — 시험은 **`$15` 함정** 위주 |

**이 문제 실행** (`./script` · **인자 없음** → **`$1` 비어 있음**):

```bash
echo "The cost is $15"
# $1 = (없음)  +  "5"  →  The cost is 5
```

**진짜 `$15` (달러 15) 출력:**

```bash
echo "The cost is \$15"
# → The cost is $15
```

**`\$`** = **`$` 기호 그대로** (변수 해석 **끔**) — 1-7.

**정리:** **`$` 뒤 숫자가 “안 읽히는” 게 아니라** — **`$1`까지 변수로 먼저 묶이고** **`5`만 남음**.

### 1-8
**문제:** **`value2=$value1`** → **`value2`에 숫자 10** · **`value2=value1`** → **문자열 `value1`**. ( O / X )

**정답:** **O**

**해설:** PDF slide 9 · **test4** — **변수에 값 넣기** 두 방식 비교.

**상황 (스크립트 test4):**

```bash
value1=10
```

이미 **`value1`** 이라는 변수에 **10**이 들어 있음.

---

**케이스 A — `$` 있음 (값 복사):**

```bash
value2=$value1
echo The resulting value is $value2
```

| 줄 | 의미 |
|----|------|
| **`value2=$value1`** | **`value1` 변수 안의 값(10)** 을 **`value2`에** 넣음 |
| **`echo … $value2`** | **`value2` 값** 출력 |

**출력:** `The resulting value is 10`

---

**케이스 B — `$` 없음 (글자 그대로):**

```bash
value2=value1
echo The resulting value is $value2
```

| 줄 | 의미 |
|----|------|
| **`value2=value1`** | **숫자 10이 아님** · **글자 `value1` 네 글자**를 문자열로 저장 |
| **`echo … $value2`** | 그 문자열 출력 |

**출력:** `The resulting value is value1`

---

**한 줄 규칙:**

| 쓴 코드 | **`value2`에 들어가는 것** |
|---------|---------------------------|
| **`value2=$value1`** | **`value1` 변수의 값** → **`10`** |
| **`value2=value1`** | **`$` 없음** → **이름 `value1` 글자 그대로** |

**`$` = “변수 **값** 꺼내기”** · **`=` 오른쪽에 `$` 빠지면** 변수 이름이 **텍스트**로 들어감.

### 1-10
**문제:** **백틱** **`` `date` ``** 는 **명령 실행 결과**를 변수·echo에 **넣는다**(command substitution). ( O / X )

**정답:** **O**

**해설:** PDF slide 10 · test5.

**이 문제가 묻는 것:** `` `date` `` 처럼 **백틱**으로 감싸면, `date`를 **글자**가 아니라 **명령**으로 실행하고, 그 **출력**을 변수나 echo에 넣는지.

**백틱(backtick):** 키보드 **`~` 옆** `` ` `` 키. 명령을 감싸면 **command substitution(명령 치환)** 이 됨.

**동작 순서:**
1. `` `명령` `` 안의 명령을 **먼저 실행**
2. 터미널에 나온 **출력 문자열**을 가져옴
3. 그 문자열이 **백틱이 있던 자리**에 들어감 (변수 대입, echo 등)

**예:** `testing=`date`` → `date` 실행 → `"Mon Sep 24 …"` 같은 문자열이 `testing`에 저장.

**요약:** 백틱 = “명령 돌리고, 결과를 여기 꽂아라” → **O**.

---

**PDF test5 — 날짜 문자열 넣기:**

```bash
testing=`date`
echo "The date and time are: " $testing
```

| 단계 | 일어나는 일 |
|------|-------------|
| ① | **`date`** 실행 → 예: `Mon Sep 24 20:23:25 EDT 2007` |
| ② | 그 **한 줄 결과**가 **`testing` 변수**에 저장 |
| ③ | **`echo … $testing`** → 위 날짜 문자열 출력 |

**백틱 없으면 (`myshell2.sh`와 비교):**

```bash
testing='date'          # 명령 실행 X → 글자 "date"만
testing=`date`          # date 실행 → "Mon Sep 24 …"
```

---

**PDF slide 10 — 로그 파일 이름:**

```bash
today=`date +%y%m%d`    # date에 옵션 → 070922 같은 짧은 날짜
ls /usr/bin -al > log.$today
# → log.070922 파일 생성
```

**`` `date +%y%m%d` ``** = **`date +%y%m%d` 실행 결과**만 **`today`에** · **`log.`** 와 **붙여서** 파일명.

**최신 bash:** **`$(date)`** = 백틱과 **같은 뜻** (`myshell1.sh`의 **`$(pwd)`**).

**정리:** **백틱** = “**이 명령 돌리고, 출력을 여기 꽂아라**” — **O**.

### 1-12
**문제:** **`command > file`** 은 **덮어쓰기(overwrite)** · **`>>`** 는 **이어 붙이기(append)**. ( O / X )

**정답:** **O**

**해설:** PDF slide 11 · `history 10.sh`.

**이 문제가 묻는 것:** 명령 출력을 파일로 보낼 때 **`>`** 와 **`>>`** 의 차이.

| 기호 | 이름 | 파일에 이미 내용이 있을 때 |
|------|------|---------------------------|
| **`>`** | **덮어쓰기(overwrite)** | **기존 내용을 지우고** 새 출력만 저장 |
| **`>>`** | **이어 붙이기(append)** | **기존 내용 뒤에** 새 출력을 추가 |

**비유:** 공책에 쓸 때 **`>`** = **새 페이지에 처음부터 다시 쓰기** · **`>>`** = **아래 줄에 이어서 쓰기**.

**PDF 예 (`history 10.sh`):**

```bash
who > test6      # ① test6을 새로 만듦 (있던 내용은 사라짐) → who 결과만
date >> test6    # ② test6 맨 뒤에 date 결과 추가 → who + date 둘 다 남음
```

**`>` 두 번이면?** `date > test6` 을 연속 두 번 실행하면 **두 번째 date만** 남음 (첫 번째는 덮어써짐).

**요약:** **`>`** = 새로 쓰기 · **`>>`** = 이어 쓰기 → **O**.

### 1-13
**문제:** **`wc < test6`** 은 **파일 내용을 표준 입력**으로 **`wc`** 에 넣는다. ( O / X )

**정답:** **O**

**해설:** PDF slide 12 · `history 10.sh`.

**이 문제가 묻는 것:** **`<`** 로 **파일 내용**을 **명령의 입력**으로 넣는지. ( **`>`** 의 반대 방향)

**`wc` 명령이란?** **w**ord **c**ount — 받은 글자를 읽어 **줄 수 · 단어 수 · 글자 수**를 센다.

```bash
wc < test6
# 예시 출력:  2  15  98
#            줄  단어  글자
```

**`test6` 안에 뭐가 들어 있나?** (1-12에서 만든 **텍스트 파일** — **실행할 스크립트가 아님**)

```bash
who > test6      # who 명령의 출력이 test6에 저장됨
date >> test6    # date 출력이 test6 맨 뒤에 추가됨
```

`test6` 내용 예:

```
sj       pts/0    2026-06-08 09:00
Mon Jun  8 09:00:00 KST 2026
```

→ **명령어가 저장된 게 아니라**, `who`·`date`가 **이미 실행된 결과(글자)** 가 파일에 적혀 있음.

**`wc < test6` 동작 순서:**

| 단계 | 일어나는 일 |
|------|-------------|
| ① | 셸이 **`test6` 파일을 연다** (실행하지 않음) |
| ② | 파일 **내용 전체**를 **`wc`의 표준 입력(stdin)** 으로 넘김 |
| ③ | **`wc`가 그 글자를 읽고** 줄·단어·글자 수를 **화면에 출력** |

**헷갈리지 말 것:**
- **`test6`를 실행**하는 것 **아님** — 그냥 **읽기만** 함
- **`wc` 변수에 넣는 것** **아님** — **표준 입력**으로 넣는 것

**방향 정리:** **`>`** = 명령 출력 → 파일 · **`<`** = 파일 내용 → 명령 입력 → **O**.

### 1-14
**문제:** **`command1 | command2`** — **`command1` 출력**을 **`command2` 입력**으로 (**pipe**). ( O / X )

**정답:** **O**

**해설:** PDF slide 13.

**`|`(pipe):** 앞 명령 **stdout** → 뒤 명령 **stdin** (1-13 **`<`** 는 파일→명령, **`|`** 는 명령→명령).

**`ls -l / | more`**

| 부분 | 뜻 |
|------|-----|
| `ls` | **list** — 목록 |
| `-l` | **long** — 자세한 형식 |
| `/` | **루트** 디렉터리 |
| `\| more` | 긴 목록을 **한 화면씩** | 
# 마크다운 표에서 |를 글자로 인식하도록 하기 위해서 \를 사용

**`rpm -qa | sort`**

**`rpm`이란?** (R**ed Hat **P**ackage **M**anager) Linux에 **설치된 프로그램(패키지)** 을 다루는 명령 — 설치·삭제·**조회** 등.

**`-q` 있음 vs 없음:**

| | 하는 일 | 예 |
|---|--------|-----|
| **`rpm` (옵션만)** | 패키지 **설치·삭제·업그레이드** | `rpm -i foo.rpm` 설치 |
| **`rpm -q`** | **조회만** (설치 상태·정보 **읽기**) | `rpm -q bash` → bash 패키지 정보 |

→ **`-q` = “건드리지 말고 물어보기”** 모드.

**`-qa`:** **`-q`** 조회 + **`-a`** **all** → **설치된 패키지 이름 전부** 나열.

**`| sort`:** 그 목록을 **알파벳 순**으로 정렬 (패키지가 많아서 pipe로 연결).

**요약:** **`|`** = 앞 출력 → 뒤 입력 → **O**.

```
wc << EOF
    ^^
    heredoc 시작 + 끝 표시 이름(마커)
line1          ← wc에게 들어가는 입력
line2
EOF            ← “여기까지 입력 끝” (마커와 같은 단어)
```

**`EOF`란?** **명령어도 아님** — 입력 **끝**을 알리는 **마커(구분자) 이름**. 관례적으로 **E**nd **O**f **F**ile 줄임. **`TEST`** 등 **아무 이름**이나 가능하지만 **시작(`<< EOF`)과 끝(`EOF`)이 같아야** 함.

**동작 순서:**

| 단계 | 일어나는 일 |
|------|-------------|
| ① | **`wc << EOF`** — heredoc 시작 |
| ② | **`line1`**, **`line2`** 가 **`wc` 입력**으로 전달 |
| ③ | **`EOF` 한 줄** — 입력 종료 |
| ④ | **`wc`** 가 2줄을 세서 출력 (예: `2  2  12`) |

**암기:** heredoc = **`<< 마커`** … **여러 줄** … **같은 마커** · 빈칸 = **`EOF`**

| | **`$(( (num1 + num2) / 2 ))`** | **`` `expr ...` ``** |

**암기:** bash 산술 = **`$(( ))`** · 외부 계산 = **`` `expr ...` ``** (공백·`\*` 주의, 1-15) — **둘 다 평균 낼 수 있지만 문법이 다름**.

**해설:** PDF slide 13.

**명령 전체 흐름:**

```
ls -l file1 file2  2>/dev/null  |  wc -l
      │                │              │
      │                │              └─ 줄 수만 출력
      │                └─ 에러 메시지 숨김
      └─ file1·file2 자세한 목록 (stdout)
```

**각 부분:**

| 부분 | 뜻 | 역할 |
|------|-----|------|
| **`ls`** | **list** | 파일·폴더 **목록** |
| **`-l`** | **long** | **자세한 형식** (권한·크기·날짜·이름) |
| **`file1 file2`** | (인자) | **이 두 파일만** 나열 (폴더 전체 X) |
| **`2>/dev/null`** | stderr 리다이렉션 | **에러 출력**을 **`/dev/null`**(쓰레기통)로 → **화면에 안 보임** |
| **`|`** | pipe | **`ls` stdout** → **`wc` stdin** (1-14) |
| **`wc -l`** | word count **-l**ines | 입력 **줄 수**만 세서 숫자 출력 |

**`wc -l` 출력이 의미하는 것:** 앞 명령(**`ls -l`**)이 낸 **줄 개수**.

**이 문제 (file1·file2 존재):**

```
-rw-r--r-- ... file1    ← 1줄
-rw-r--r-- ... file2    ← 1줄
```

→ **`wc -l` = `2`** (`total` 헤더 **없음** — **파일 이름을 직접** 줄 때)

**참고:** **폴더**를 `ls -l` 하면 맨 위 **`total N` 1줄** + 파일 줄 → 파일 2개면 **3**이 될 수 있음. **이 문제는 `file1 file2` 직접 지정**이므로 **2**.
