## 유형 1. 개념 O/X

> **목표:** Lab에서 틀리면 안 되는 **개념**부터 잡기. ( O / X )

---

### 1-1
**문제:** `CONTRIBUTING.md`를 만들기만 하고 `git add`를 하지 않았다. 이 파일은 **Untracked** 상태이다. ( O / X )

**정답:** **O**

**해설:** PDF 슬라이드 12: `git status`에 `Untracked files:` 아래에 나옵니다. `git add` 전까지는 커밋 대상이 아닙니다.

---

### 1-2
**문제:** `git commit`만 하고 아직 `git push`를 하지 않았을 때 `Your branch is ahead of 'origin/master' by N commits.` 메시지가 나올 수 있다. ( O / X )

**정답:** **O**

**해설:** 로컬에만 있고 **원격에는 아직 없는 commit**이 N개 있다는 뜻. push하면 원격에 올라갑니다.

---

### 1-3 (`commit --amend`)
**상황:** commit 했는데 **파일을 빼먹음** · `git add forgotten_file` 후:

```bash
git commit --amend
```

**문제:** `git commit --amend`는 **방금 직전(마지막) commit을 수정**한다. ( O / X )

**정답:** **O**

**해설:**

**amend** = 영어 **“고치다·보완하다”** · Git에서는 **직전 commit을 덮어써서 수정**.

| | **`git commit`** | **`git commit --amend`** |
|--|------------------|------------------------|
| 하는 일 | **새** commit **추가** | **마지막** commit **수정** (새로 안 쌓음) |
| commit 개수 | +1 | **그대로** (내용만 바뀜) |
| commit ID | 새 hash | **바뀜** (내용이 달라져서) |

**`--` 는 왜 붙이나?**

Git **긴 옵션** 표기 · `--amend` = “amend 옵션 켜기”.

| 표기 | 예 | 뜻 |
|------|-----|-----|
| **`-` 한 개 + 한 글자** | `-m` | 짧은 옵션 (**m**essage) |
| **`--` 두 개 + 단어** | `--amend` | 긴 옵션 (이름 그대로) |

→ `5-1` 의 `-m` 과 같은 **옵션**인데, **긴 이름**이라 `--` 를 붙임.

(참고: `git checkout -- file` 의 `--` 는 **옵션 끝** 표시로 **다른 용도** · `--amend` 는 **옵션 이름 자체**.)

**PDF 슬라이드 41~42:** 빼먹은 파일 `add` 후 `--amend` → **이전 commit에 합침** (`1-8` X 와 구분).

---

### 1-4
**문제:** `git diff --staged`와 `git diff --cached`는 **같은 것**을 본다. ( O / X )

**정답:** **O**

**해설:** PDF 슬라이드 19~20: 둘 다 **스테이징된 변경 vs 마지막 commit**을 봅니다. 5-1의 `--cached`와 동일 개념입니다.

---

### 1-5 (`commit -m` · staged 만)
**상황:** Lab PDF 슬라이드 21~22 · **README** 는 `git add` 함 · **CONTRIBUTING.md** 는 수정만 하고 **add 안 함**.

```bash
git commit -m "Contributing is modified"
```

**문제:** `-m` 메시지에 "Contributing"이 있어도, **staged 된 파일만** commit 된다. ( O / X )

**정답:** **O**

**해설:**

**`-m`** = **message** · commit **설명**을 명령줄에 적음 (`5-1` `1-11`).

```bash
git commit -m "Contributing is modified"
#            ↑ 메모(설명)일 뿐 · **어떤 파일 넣을지 정하지 않음**
```

| | 결정하는 것 |
|--|-------------|
| **`-m "…"`** | commit **메시지**(글자)만 |
| **`git add`** | **어떤 파일**이 commit 에 들어갈지 |

→ 메시지에 Contributing 이라 써도 **`add` 안 한 CONTRIBUTING.md 는 안 들어감** · **README만** commit (`6-3`).

**헷갈리면 X:** 메시지 = **이름표** · 파일 선택 = **`add`** 가 함.

---

### 1-6
**문제:** `git diff` (옵션 없음)는 **작업 폴더 ↔ 스테이징** 차이를 본다. 원격 서버와 비교하는 명령이다. ( O / X )

**정답:** **X**

**해설:** `git diff` = `add` **하지 않은** 차이. 원격 비교는 `fetch`/`pull`/`push` 영역입니다.

---

### 1-7
**문제:** `git commit --amend`는 **새 commit을 추가**하는 명령이다. ( O / X )

**정답:** **X**

**해설:** `--amend` = 직전 commit **덮어쓰기**. 새 commit 추가가 아닙니다.

---

### 1-8
**문제:** 한 번도 `add` 안 한 **새 파일**은 Untracked, 이미 추적 중인 파일의 **수정**은 Modified(unstaged)이다. ( O / X )

**정답:** **O**

**해설:** Untracked = Git이 아직 관리하지 않는 파일 · Modified = 추적 중인데 `add` 전 수정.

---

### 1-9
**문제:** `git diff`와 `git diff --cached`는 각각 **unstaged** vs **staged** 변경을 본다. ( O / X )

**정답:** **O**

**해설:** `diff` = 작업 폴더 vs 스테이징 · `--cached`/`--staged` = 스테이징 vs 마지막 commit.

---

### 1-10
**문제:** `Your branch is behind 'origin/main' by 2 commits.`는 원격이 로컬보다 **2 commit 앞서 있음**을 뜻한다. ( O / X )

**정답:** **O**

**해설:** `ahead`의 반대. 보통 **`git pull`**로 맞춥니다.

---

### 1-11
**문제:** `Your branch is up-to-date with 'origin/master'.`는 **로컬과 원격이 같은 commit**까지 맞춰져 있음을 뜻한다. ( O / X )

**정답:** **O**

**해설:** PDF Lab slide 12·17. push/pull **할 것 없음** — 이후 수정·commit하면 `ahead` 등으로 바뀜.

## 유형 5. 상태·메시지 예측

> **`git status` / `-s` 표기** (공지: command outcomes)

---

### 5-1 (Lab 핵심 시나리오)
**배경:** `origin/master`와 동기화됨. 아래 실행 직후:

```bash
echo 'A new line is added 2' >> README
git add README
echo 'A new contributor is added 2' >> CONTRIBUTING.md
git status
```

**문제:** `README` / `CONTRIBUTING.md` 각각 **어느 섹션**에 나오는가?

**정답:**  
- `README` → **Changes to be committed** (staged)  
- `CONTRIBUTING.md` → **Changes not staged for commit** (modified, unstaged)

**해설:** `README`만 `add` 했고, `CONTRIBUTING.md`는 수정만 했습니다. **한 번에 둘 다 staged가 아님** — Lab 시험 단골 유형입니다.

---

### 5-2
**상황:** 5-1 다음 `git commit -m "Contributing is modified"` **한 번만** 실행. push 안 함.

**문제:**  
① `Your branch is ahead of 'origin/master' by ___ commit.` — 빈칸 숫자는?  
② `CONTRIBUTING.md`는 어떤 상태로 나오는가?

**정답:**  
① **1**  
② **Changes not staged for commit: modified: CONTRIBUTING.md**

**해설:** PDF 슬라이드 23. push 안 했으므로 ahead 1. `CONTRIBUTING.md`는 여전히 add/commit 안 된 수정입니다.

---

### 5-3
**상황:** `CONTRIBUTING.md`, `README`를 새로 만들었고 **둘 다 `git add` 안 함**. `git status` 실행.

**문제:**  
(1) 이 파일들은 **Untracked files**에 나오는가? ( O / X )  
(2) `nothing added to commit but untracked files present` 문구가 나오는가? ( O / X )

**정답:** (1) **O** (2) **O**

**해설:** PDF 슬라이드 12. 파일을 **만들기만** 했고 `git add`를 **한 번도 안 함** → `Untracked files` 아래에 나열됩니다.

---

### 5-4
**상황:** 5-3 다음 `git add CONTRIBUTING.md`만 실행 후 `git commit -m '2nd version'`.

**문제:** commit에 포함되는 파일은? (`CONTRIBUTING.md` / `README` / 둘 다)

**정답:** **CONTRIBUTING.md** 만

**해설:** PDF 슬라이드 13. `add`한 것만 commit됩니다. `README`는 여전히 untracked입니다.

---

### 5-5
**상황:** 5-1과 같이 `CONTRIBUTING.md`만 수정된 채로 남아 있다. `git status` 힌트 메시지.

**문제:** 빈칸을 채우시오.

```
(use "git reset HEAD <file>..." to ______)
(use "git checkout -- <file>..." to ______ changes in working directory)
```

**정답:** **unstage** (또는: 스테이징에서 내리다) / **discard** (또는: 버리다)

**해설:** `reset HEAD` = unstage · `checkout --` = 작업 폴더 수정 **폐기**. 5-1의 2-9, 2-10과 연결됩니다.

---

### 5-6 (`status -s`)
**상황:** 새 파일 `new.txt`(untracked), 수정된 tracked 파일 `README.md`(unstaged).

**문제:** `git status -s`에 나올 수 있는 표기는? (해당하는 것 모두)

**정답:** `?? new.txt` · ` M README.md` (2열에 M)

**해설:** `??` = **untracked**. 1열 M = staged, **2열** M = working tree만 수정 (5-1 유형 5 참고).

---

### 5-7 (`behind` 메시지)
**상황:** `git status` 출력: `Your branch is behind 'origin/main' by 2 commits.`

**문제:** (1) 의미를 한 줄로? (2) 로컬을 맞추려면 보통?

**정답:** (1) 원격에 로컬보다 **2 commit 앞서 있음** (2) **`git pull`**

**해설:** `ahead`의 반대. 5-2 유형 1-2·5-2는 ahead를 다룸 — **behind**도 시험에 나올 수 있음.

## 유형 6. diff·log 출력 예측

---

### 6-1 (Lab 시나리오 — `git diff`)
**배경:** 유형 5-1과 동일 상태 (`README`만 `add`, `CONTRIBUTING.md`는 수정만).

**문제:** `git diff` (옵션 없음) — **어떤 파일**의 차이가 보이는가? `README` / `CONTRIBUTING.md` / 둘 다 / 없음

**정답:** **CONTRIBUTING.md** 만

**해설:** `git diff` = **아직 `add`하지 않은 수정**만. `README`는 이미 `add`해서 작업 폴더 = 스테이징 → **안 나옴**.

---

### 6-2 (Lab 시나리오 — `--cached`)
**배경:** 유형 5-1과 동일 상태.

**문제:** `git diff --cached` (또는 `--staged`) — **어떤 파일**의 차이가 보이는가?

**정답:** **README** 만

**해설:** staged vs 마지막 commit. PDF 슬라이드 19~20. `CONTRIBUTING.md`는 스테이징 안 됐으므로 `--cached`에 없음.

---

### 6-3 (Lab 시나리오 — commit 포함)
**배경:** 유형 5-1 상태에서 `git commit -m "Contributing is modified"` **한 번만** 실행.

**문제:** commit에 **포함된 파일** / **포함되지 않은 파일**은?

**정답:**  
- 포함: **README**  
- 미포함: **CONTRIBUTING.md** (여전히 작업 폴더만 수정된 상태)

**해설:** PDF 슬라이드 21~22. 메시지와 **무관하게** staged 된 것만 들어갑니다.

---

### 6-4 (종합 — 시험 스타일)
**상황:** 아래를 **순서대로** 실행했다.

```bash
git status   # clean, origin/master와 up-to-date
echo "line1" >> fileA.txt
git add fileA.txt
echo "line2" >> fileB.txt
```

**문제:**  
(1) `git status`에서 `fileA.txt` / `fileB.txt` 각각 어느 섹션인가?  
(2) `git diff`에 나오는 파일은?  
(3) `git diff --cached`에 나오는 파일은?  
(4) `git commit -m "msg"` 한 번 후, `fileB.txt`는 저장소에 반영되었는가? ( O / X )

**정답:**  
(1) `fileA` → Changes to be committed / `fileB` → Changes not staged  
(2) **fileB.txt**  
(3) **fileA.txt**  
(4) **X** (fileB는 commit에 안 들어감)

**해설:** PDF 슬라이드 17~22와 **동일 패턴**. `fileA`↔`README`, `fileB`↔`CONTRIBUTING.md`로 외우면 됩니다.

### 6-5 (종합 표)
**상황:** Lab 시나리오 — `README`만 `add`, `CONTRIBUTING.md`는 수정만 (commit 전).

**문제:** 단계별로 `git diff` / `git diff --cached` 를 O/X로 채우시오.

| 파일 | git diff | git diff --cached |
|------|----------|-------------------|
| README | | |
| CONTRIBUTING.md | | |

**정답:**

| 파일 | git diff | git diff --cached |
|------|----------|-------------------|
| README | X | O |
| CONTRIBUTING.md | O | X |

**해설:** 유형 6-1~6-2 종합. 시험 **표 채우기** 형태 대비. `fileA`/`fileB` 종합(6-4)도 같은 패턴입니다.

### 6-6 (Lab — `git diff HEAD`)
**상황:** Lab §5-1과 같음 — `README`만 `add`, `CONTRIBUTING.md`는 수정만(unstaged).

**문제:** `git diff HEAD`에 **나오는 파일**은? (`README` / `CONTRIBUTING.md` / 둘 다 / 없음)

**정답:** **둘 다**

**해설:** `HEAD` = 마지막 commit. unstaged(`CONTRIBUTING`) + staged(`README`) **모두** HEAD와 비교. `git diff`(옵션 없음)는 **unstaged만** → 6-1·6-2와 구분.
