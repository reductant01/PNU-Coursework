**5-1과의 관계:** 5-1은 Git **개념·기본 명령**, 5-2는 **실습(Lab)** — `status`/`diff`가 섞인 상황, `--amend`, 원격과의 앞섬(ahead) 등을 다룹니다.

**먼저 읽기 — 파일 상태 네 가지 (Lab PDF)**

| 상태 | 의미 | `git status`에 보이는 곳 |
|------|------|--------------------------|
| Untracked | Git이 아직 추적 안 함 | Untracked files |
| Modified (unstaged) | 고쳤지만 `add` 안 함 | Changes **not staged** |
| Staged | `add` 함, `commit` 전 | Changes **to be committed** |
| Committed | `commit` 완료 | (clean 또는 ahead 메시지) |

```
[Untracked] --git add--> [Staged] --git commit--> [Committed]
[Modified]  --git add--> [Staged]
```

**이 파일 읽는 법:** **상황 → 문제**만 보고 푼 뒤, **정답·해설**을 확인하세요.

## 1. 개념·OX (Lab PDF)

### 1-1
**묻는 것:** Git이 추적하지 않는 새 파일 상태

`CONTRIBUTING.md`를 만들기만 하고 `git add`를 하지 않았다. 이 파일은 **Untracked / Staged / Committed** 중 무엇인가?

**정답:** **Untracked** (추적되지 않은 파일)

**해설:** PDF 슬라이드 12: `git status`에 `Untracked files:` 아래에 나옵니다. `git add` 전까지는 커밋 대상이 아닙니다.

---

### 1-2
**묻는 것:** 로컬이 원격보다 앞선 상태

`git commit`만 하고 아직 `git push`를 하지 않았다.  
`git status`에 `Your branch is ahead of 'origin/master' by 1 commit.` 이 나온다.  
이 말은 무엇을 뜻하는가? (한 줄)

**정답:** 로컬에만 있고 **원격(origin/master)에는 아직 없는 commit이 1개** 있다.

**해설:** push하면 원격에 올라갑니다. pull과 반대 개념입니다.

---

### 1-3
**묻는 것:** `git commit --amend`의 역할

**정답:** **방금 직전(마지막) commit을 수정**한다. (메시지 변경, 빠뜨린 파일 추가 등)

**해설:** PDF 슬라이드 41~42: `forgotten_file`을 `add`한 뒤 `--amend`로 **이전 commit에 합침**. commit ID(`7d96d1e` → `1f8c354`)가 **바뀝니다**.

---

### 1-4
**묻는 것:** `git diff --staged`와 `git diff --cached`

**정답:** **같은 것**을 본다. (스테이징된 변경 vs 마지막 commit)

**해설:** PDF 슬라이드 19: `git diff –staged (or staged)` / 슬라이드 20: `git diff --cached` — README 스테이징 내용이 동일하게 출력됩니다. 5-1의 `--cached`와 동일 개념입니다.

## 3. 결과 예측 — Lab 핵심 시나리오 (PDF 슬라이드 17~23)

### 배경 (문제 풀기 전에 읽기)

초기 상태: `origin/master`와 동기화됨 (`Your branch is up-to-date with 'origin/master'`).

```bash
echo 'A new line is added 2' >> README
git add README
echo 'A new contributor is added 2' >> CONTRIBUTING.md
git status
```

---

### 3-1
**문제:** 위 직후 `git status`에서  
- `README`는 **어느 섹션**에 나오는가? (`Changes to be committed` / `Changes not staged` / `Untracked`)  
- `CONTRIBUTING.md`는?

**정답:**  
- `README` → **Changes to be committed** (staged)  
- `CONTRIBUTING.md` → **Changes not staged for commit** (modified, unstaged)

**해설:** `README`만 `add` 했고, `CONTRIBUTING.md`는 수정만 했습니다. **한 번에 둘 다 staged가 아님** — Lab 시험 단골 유형입니다.

---

### 3-2
**문제:** 같은 상태에서 `git diff` (옵션 없음) — **어떤 파일**의 차이가 보이는가? `README` / `CONTRIBUTING.md` / 둘 다 / 없음

**정답:** **CONTRIBUTING.md** 만

**해설:** 먼저 두 파일이 **어느 단계까지 갔는지**를 보면 이해가 쉽습니다.

| 파일 | 지금까지 한 일 | 상태 |
|------|----------------|------|
| `README` | `echo`로 수정 → **`git add README`까지 함** | 스테이징됨 (commit 대기) |
| `CONTRIBUTING.md` | `echo`로 수정만 함 → **`git add` 안 함** | 작업 폴더만 수정됨 |

`git diff` (옵션 없음)는 **「아직 `add`하지 않은 수정」** 만 보여 줍니다.  
즉 **작업 폴더 ↔ 스테이징** 사이에 차이가 있는 파일만 출력합니다.

- **`README`** — 이미 `add`해서 작업 폴더 = 스테이징 내용이 **같음** → `git diff`에 **안 나옴**
- **`CONTRIBUTING.md`** — 작업 폴더만 바뀌고 스테이징에는 반영 안 됨 → `git diff`에 **나옴**

PDF 슬라이드 18처럼 터미널에는 대략 이렇게 보입니다 (`CONTRIBUTING.md`만):

```
diff --git a/CONTRIBUTING.md b/CONTRIBUTING.md
...
+A new contributor is added 2
```

`README` 내용을 보려면 **`git diff --cached`** (3-3)를 써야 합니다.

---

### 3-3
**문제:** 같은 상태에서 `git diff --cached` (또는 `--staged`) — **어떤 파일**의 차이가 보이는가?

**정답:** **README** 만

**해설:** staged vs 마지막 commit. PDF 슬라이드 19~20. `CONTRIBUTING.md`는 스테이징 안 됐으므로 `--cached`에 없음.

---

### 3-4
**문제:** 이 상태에서 `git commit -m "Contributing is modified"` **한 번만** 실행했다.  
**스테이징되어 있던 파일만** commit된다.  
commit에 **포함된 파일** / **포함되지 않은 파일**은?

**정답:**  
- 포함: **README**  
- 미포함: **CONTRIBUTING.md** (여전히 작업 폴더만 수정된 상태)

**해설:** PDF 슬라이드 21~22. 메시지에 "Contributing"이 있어도 **staged 된 것만** 들어갑니다. `CONTRIBUTING.md`는 commit 후에도 modified로 남습니다.

---

### 3-5
**문제:** 3-4 직후 `git status`에서  
① `Your branch is ahead of 'origin/master' by ___ commit.` — 빈칸 숫자는?  
② `CONTRIBUTING.md`는 어떤 상태로 나오는가?

**정답:**  
① **1**  
② **Changes not staged for commit: modified: CONTRIBUTING.md**

**해설:** PDF 슬라이드 23. push 안 했으므로 ahead 1. `CONTRIBUTING.md`는 여전히 add/commit 안 된 수정입니다.

---

### 3-6 (빈칸 — status 메시지)
**상황:** 3-5와 같이 `CONTRIBUTING.md`만 수정된 채로 남아 있다.

## 4. 결과 예측 — Untracked · 짧은 status

### 4-1
**상황:** `CONTRIBUTING.md`, `README`를 새로 만들었고 **둘 다 `git add` 안 함**. `git status` 실행.

**문제:** PDF처럼 출력될 때, 이 파일들은 **Untracked files**에 나오는가?  
`nothing added to commit but untracked files present` 문구가 나오는가? (O/X)

**정답:** **둘 다 O (예)**

**해설:** **「PDF처럼」** = 5-2 Lab PDF 슬라이드 12에 나온 `git status` 화면과 같다는 뜻입니다.  
터미널에 대략 **아래처럼** 출력됩니다.

```
On branch master
Your branch is up-to-date with 'origin/master'.

Untracked files:
  (use "git add <file>..." to include in what will be committed)

        CONTRIBUTING.md
        README

nothing added to commit but untracked files present (use "git add" to track)
```

**한 줄씩 읽기**

| 출력 | 의미 |
|------|------|
| `On branch master` | 지금 `master` 브랜치에 있음 |
| `Your branch is up-to-date with 'origin/master'.` | 원격과 동기화된 상태 |
| **`Untracked files:`** | Git이 **아직 관리하지 않는** 새 파일 목록 |
| `CONTRIBUTING.md` / `README` | 두 파일 모두 이 **Untracked** 아래에 나열됨 |
| **`nothing added to commit but untracked files present`** | commit할 staged 파일은 **없고**, 추적 안 하는 파일만 **있다** |

**왜 Untracked인가?**

- 파일을 **만들기만** 했고 `git add`를 **한 번도 안 함**
- Git 입장에서는 “이 파일을 버전 관리할지” 아직 **등록(track) 전**
- 그래서 `Changes to be committed`나 `modified`가 **아니라** `Untracked files`에만 보임

**문제 두 문장에 대한 답**

1. **Untracked files에 나오는가?** → **O** — 위 목록처럼 두 파일 모두 그 아래에 나옴  
2. **`nothing added to commit but untracked files present` 나오는가?** → **O** — 맨 아래 그 문장이 그대로 출력됨

---

## 6. 표 완성 · 비교 (5-1 복습 + 5-2 추가)

**문제:** 설명 칸을 채우시오.

| 명령 | 설명 (빈칸) |
|------|-------------|
| `git diff` | |
| `git diff --staged` | |
| `git commit --amend` | |
| `git push origin master` | |

---

**정답·해설**

| 명령 | 비교·대상 | 설명 (시험에 적을 분량) |
|------|-----------|-------------------------|
| `git diff` | **작업 폴더 ↔ 스테이징** | `add` **하지 않은** 차이를 본다 |
| `git diff --staged` | **스테이징 ↔ 마지막 commit (HEAD)** | `add` **한** 차이를 본다 (`--cached`와 같음) |
| `git commit --amend` | **직전 commit** | 마지막 commit을 **덮어써서** 수정한다 (메시지·파일 추가 등) |
| `git push origin master` | **로컬 → 원격** | 로컬 commit을 원격 **`origin`의 `master` 브랜치**에 올린다 |

**외울 때 (한 줄만 적어도 될 때)**

| 명령 | 한 줄 답 |
|------|----------|
| `git diff` | 작업 폴더 vs 스테이징 |
| `git diff --staged` | 스테이징 vs 마지막 commit |
| `git commit --amend` | 직전 commit 수정 |
| `git push origin master` | origin/master로 push |

**5-2 Lab과 연결:** `README`만 `add`한 상태 → `git diff`에는 `CONTRIBUTING.md`, `git diff --staged`에는 `README` (§3 참고).

## 자주 헷갈리는 것 (5-2 Lab)

| 헷갈림 | 정리 |
|--------|------|
| commit 메시지 vs 실제 내용 | `-m` 문자열과 **무관하게**, **staged 된 파일만** commit |
| `git diff` vs `--cached` | unstaged vs staged (서버와 비교 **아님**) |
| ahead of origin | push 안 한 로컬 commit 개수 |
| `--amend` | 새 commit 추가가 아니라 **직전 commit 덮어쓰기** |
| `--staged` vs `--cached` | **같은 의미** (5-2 PDF) |
| Untracked vs Modified | 한 번도 `add` 안 한 **새 파일** vs 이미 추적 중인 파일의 **수정** |
