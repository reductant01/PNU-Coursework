### 1-1

**해설:** PDF slide 3. 파일 권한을 쓰려면 **누가(u/g/o)** 인지 알아야 하므로, 먼저 사용자 계정을 다룬다.

### 1-2

**정답:** **X**

**해설:** PDF slide 3. 로그인은 **login name**(8자 이하 영숫자) + **password**. UID는 시스템 내부 식별용 **숫자**.

### 1-3
**문제:** 현재 Linux는 사용자 **비밀번호**를 주로 **`/etc/shadow`** 에 따로 저장한다. ( O / X )

**정답:** **O**

**해설:** PDF slide 5~6. `/etc/passwd`의 password 칸은 **`x`** 로 두고, 실제 암호화 비밀번호는 shadow 파일에 둔다.

### 1-4

**해설:** PDF slide 6. 일반 사용자는 shadow를 읽을 수 없다.

### 1-5
**문제:** `/etc/passwd`를 **텍스트 편집기로 직접** 고치는 것은 **안전한** 관행이다. ( O / X )

**정답:** **X**

**해설:** PDF slide 5. 파일이 깨지면 **아무도(root 포함) 로그인 불가** — `useradd`·`usermod` 등 **표준 명령**을 써야 한다.

### 1-6
**문제:** `userdel` **기본**(옵션 없음)은 `/etc/passwd` 정보만 지우고, 그 사용자 **HOME 디렉터리 파일**은 그대로 둔다. ( O / X )

**정답:** **O**

**해설:** **`userdel`** = **user delete**(사용자 **삭제** 명령). Linux 계정 목록(`/etc/passwd` 등)에서 **그 사용자 등록을 지우는** 명령입니다.

- **옵션 없음:** “이 사람 계정은 없앤다”만 하고, `/home/사용자이름` 같은 **HOME 폴더·그 안 파일은 남길 수 있음** → 문제 **O**
- **`-r`** = **recursive**(재귀) — 계정 삭제 + **HOME 디렉터리·메일 폴더까지 같이 삭제** (PDF slide 11)

**비유:** 회원 탈퇴(계정만 삭제) vs 탈퇴 + **개인 폴더까지 통째로 삭제**(`-r`).

### 1-7
**문제:** **`umask 0044`** 는 새 **일반 파일** 기본 권한 **666**에서 umask 값을 **뺀** 결과를 만든다. ( O / X )

**정답:** **O**

**해설:** **`chmod`** 와 **`umask`** 는 **완전히 다른 명령**입니다. **`0044` 숫자가 같아도 하는 일이 다릅니다.**

| | **`chmod 044 …`** | **`umask 0044`** |
|---|-------------------|------------------|
| **언제** | **이미 있는** 파일·폴더 | **`umask` 친 뒤 새로 만드는** 파일·폴더 |
| **하는 일** | 권한을 **그 숫자로 덮어씀**(절대 설정) | **기본값에서 빼 줄** 마스크 **설정** |
| **예** | `chmod 644 a.txt` → 그 파일이 **644** | `umask 0044` 후 `touch b` → **b**는 **622** (강의식 666−044) |

**`umask 0044` (문제 O):**
- **새 일반 파일** 기본 **666** → **666 − 044 = 622** (`rw- -w- -w-`)
- **새 디렉터리** 기본 **777** → **777 − 044 = 733**
- `0044`와 `044`는 umask에서 **같은 마스크**로 쓰는 경우가 많음 (앞 0은 자릿수 표기)

**`chmod 044` (비교 — umask 아님):**
- `chmod 044 file` = 그 **file 하나**의 권한을 **044로 설정** (`--r--r--` — owner는 권한 없음)
- “666에서 빼기” **아님** · **umask와 혼동하면 X**

**정리:** `umask 0044` = “앞으로 만들 파일, **666에서 044만큼 빼서** 권한 정해라” · `chmod` = “**지금 이 파일** 권한을 **이 숫자로** 바꿔라”. (`history 2.sh` 147~150행)

### 1-8
**문제:** 디렉터리에 **`x`(execute) 권한**이 없으면 **`cd`로 들어갈 수 없다.** ( O / X )

**정답:** **O**

**해설:** `history 2.sh` 29~30행. `chmod -x subDir3` 후 `#cd subDir3 (permission denied)`.

---

### 1-9
**문제:** **`chmod +x file`** 은 **소유자(user)에게만** 실행 권한을 준다. ( O / X )

**정답:** **X**

**해설:** `chmod`는 **누구(u/g/o/a)** 에게 **무엇(r/w/x)** 을 **어떻게(+/−/=)** 할지 정합니다.

| 글자 | 영문 | 뜻 |
|------|------|-----|
| **u** | **U**ser | **소유자**(파일 주인) |
| **g** | **G**roup | **그룹**(같은 그룹 멤버) |
| **o** | **O**thers | **그 밖의 사람**(others) |
| **a** | **A**ll | **u+g+o 전부** |

`chmod +x file`처럼 **u/g/o/a를 안 쓰면** Linux는 **a(all)** 로 간주 → **소유자·그룹·others 모두**에 `x` 추가.  
소유자만 주려면 **`chmod u+x file`**. (`history 2.sh`의 `chmod +x myMain`은 **all**)

---

### 1-10
**문제:** 8진 권한에서 **r=4, w=2, x=1** 이다. **`5` = r+x** 이다. ( O / X )

**정답:** **O**

**해설:** 권한 한 글자씩은 영어 단어의 **첫 글자**입니다.

| 글자 | 영문 | 뜻 | 8진 값 |
|------|------|-----|--------|
| **r** | **R**ead | **읽기** | 4 |
| **w** | **W**rite | **쓰기** | 2 |
| **x** | e**X**ecute | **실행** | 1 |

`5` = 4+1 = **r+x** → **읽기+실행**, **쓰기(w) 없음**. (`history 2.sh` 33~36행)

### 1-11
**문제:** **`passwd`** 로 **다른 사람** 비밀번호를 바꿀 수 있는 것은 **root** 뿐이다. ( O / X )

**정답:** **O**

**해설:** **`passwd`** = **pass word**(비밀번호 **설정·변경** 명령). “어디 파일을 연다”가 아니라, **시스템이 허용된 방식으로** 비밀번호를 바꿔 주는 **프로그램**입니다.

| 파일 | 역할 |
|------|------|
| **`/etc/passwd`** | 로그인 이름, UID, HOME … **계정 정보**. password 칸은 **`x`** 만 → “비밀번호는 **shadow에 있음**” 표시 |
| **`/etc/shadow`** | **암호화된 비밀번호** 실제 저장 (root·특수 프로그램만 접근) |

`passwd test` 실행 시:
1. **`passwd` 프로그램**이 새 비밀번호를 입력받음  
2. 암호화해서 **`/etc/shadow`의 해당 사용자 줄**을 **갱신**  
3. **`/etc/passwd`의 `x`는 그대로** — passwd 파일에 평문·암호문을 **직접 쓰지 않음**

**문제의 “root만 다른 사람 비밀번호 변경”:** 일반 사용자는 **`passwd`**(자기 것)만 · root는 **`passwd 다른사람`** 가능 — 둘 다 최종 저장 위치는 **`/etc/shadow`**.

**정리:** 비밀번호가 passwd 파일에 **없다** = 저장 **위치**가 shadow · **`passwd`로 바꾼다** = shadow 안 **암호화 값을 프로그램이 수정** (PDF slide 13).

### 1-12
**문제:** `ls -l` 맨 앞 **`d`** 는 **디렉터리**, **`-`** 는 **일반 파일**을 뜻한다. ( O / X )

**정답:** **O**

**해설:** **`d`는 `ls -l` 명령 안에 있는 글자가 아닙니다.** `ls -l`을 **실행했을 때 나오는 출력** 맨 **첫 글자**입니다.

```bash
ls -l
```

```
drwxr-xr-x  2 hwj hwj 4096 ...  mydir      ← 맨 앞 d = di**r**ectory (디렉터리)
-rw-rw-r--  1 hwj hwj  737 ...  myfile.sh  ← 맨 앞 - = 일반 **파일**
```

| 맨 앞 1글자 | 의미 (시험) |
|-------------|-------------|
| **`d`** | **d**irectory — **디렉터리** |
| **`-`** | regular file — **일반 파일** |

10칸 권한 **`drwxr-xr-x`** 의 **`d`** 와 같은 뜻입니다. (`history 2.sh` 121~124행 · `Lecture/ShellScriptProgram/test` 참고)  
그 외 `l`(link) 등도 있으나 시험은 **`-` vs `d`** 위주.

**해설:** `history 2.sh` 153행. `o` = others · `-` = 빼기 · `r` = read.

### 1-14
**문제:** **`useradd -D`** 는 **새 사용자를 추가**하는 명령이다. ( O / X )

**정답:** **X**

**해설:** **`useradd`** = **user add**(사용자 **추가**). **`-D`** = **D**efaults(**기본값**).

| 명령 | 의미 |
|------|------|
| **`useradd -D`** | 새 사용자를 만드는 게 **아님** — `GROUP=`, `HOME=`, `SHELL=` 등 **시스템 기본 설정만 출력** (PDF slide 7) |
| **`useradd test`** | 사용자 **`test`** 계정 **추가** |

```bash
useradd -D          # 기본값 보기 (추가 X)
useradd test        # test 사용자 추가 (추가 O)
```

**정리:** 문제는 “`-D` = 사용자 추가” → **X** · `-D` = **Default(기본값) 표시**.

> **「이런 일을 할 때 빈칸에 뭐?」**

### 2-1
**상황:** 배포판 **기본 useradd 설정**(`GROUP`, `HOME`, `SHELL` …)을 본다. (PDF slide 7)

```bash
/usr/sbin/useradd ______
```

**정답:** `-D`

**해설:** **`-D`** = **D**efaults(**기본값** 표시). `SHELL=/bin/bash`, `SKEL=/etc/skel` 등 출력.

**왜 `/usr/sbin/useradd` 인가?**

| 부분 | 의미 |
|------|------|
| **`useradd`** | 명령 **이름** — 터미널에 **`useradd -D`** 만 쳐도 **같은 프로그램** 실행 (PATH에 있으면) |
| **`/usr/sbin/`** | 그 프로그램 **실행 파일이 있는 폴더 경로** (전체 pathname) |

- **`/usr/sbin`** = 시스템 **관리용** 명령(`useradd`, `userdel` …)이 모여 있는 곳. **root**가 쓰는 도구가 많음.
- PDF·교재는 “**어느 파일**을 실행하는지”를 보여 주려고 **`/usr/sbin/useradd`** 처럼 **전체 경로**를 씀.
- 시험·실습에서는 **`useradd -D`** 만 써도 됨 — **명령은 동일**, 앞 경로는 **위치 표기**일 뿐.

---

### 2-2
**상황:** 사용자 **`test`** 와 **HOME 디렉터리·skel 파일**까지 한 번에 만든다.

```bash
/usr/sbin/useradd ______
```

**정답:** `test` (옵션 없이 이름만 — PDF 예: `# useradd test`)

**해설:** **`useradd test`** = **`test`라는 새 **사용자 계정**을 만든다** — 맞습니다.

계정만 등록하면 로그인해도 **쓸 폴더·설정 파일이 없음** → Linux가 **함께** 준비합니다.

| `useradd test`가 하는 일 | 설명 |
|--------------------------|------|
| ① `/etc/passwd`에 **`test` 계정 추가** | UID, HOME 경로, shell 등 **등록** |
| ② **`/home/test` HOME 디렉터리 생성** | 그 사용자 **전용 작업 폴더** |
| ③ **`/etc/skel` → `/home/test` 복사** | `.bashrc`, `.bash_profile` 등 **시작용 템플릿 파일** |

**`/etc/skel`** = **skeleton**(뼈대) — **새 사용자마다 똑같이 넣어 줄 기본 파일 묶음**.  
“계정 만들기”와 “HOME + 기본 설정 파일 만들기”가 **한 번에** 이뤄지는 것이 `useradd`입니다. (PDF slide 7~8)

**정리:** `test` = **만들 계정 이름** · “파일을 왜?” → **로그인할 사용자의 홈·쉘 설정**을 자동으로 채워 주기 위함.

---

### 2-3
**상황:** 사용자 **`test`** 를 지우면서 **HOME·메일 디렉터리**까지 삭제. (PDF slide 11)

```bash
/usr/sbin/userdel ______ test
```

**정답:** `-r`

**해설:** **`-r`** = **r**ecursive(**재귀**) — HOME·메일 폴더까지 삭제. 옵션 없으면 passwd 항목만 삭제.

**왜 `-r`은 소문자?** `userdel`·`rm` 등에서 **“폴더 통째로”** 는 관례적으로 **소문자 `-r`**. 명령마다 옵션 문자가 **각자 정해져 있음** — 전부 대문자/소문자 규칙은 **없음**.

---

### 2-4
**상황:** 계정 **`test`** 를 **잠금**(로그인 불가). (PDF slide 12 · usermod)

```bash
usermod ______ test
```

**정답:** `-L`

**해설:** **`-L`** = **L**ock(**잠금**) · **`-U`** = **U**nlock(**해제**).

**왜 `-L`/`-U`는 대문자?** 같은 `usermod`에 **소문자 `-l`** 이 이미 **로그인 이름 변경**(login name)에 쓰임 → **잠금**은 **대문자 `-L`** 로 **구분** (PDF slide 12).  
**`-r`(소문자)** 과 **`-L`(대문자)** 는 **서로 다른 명령**(`userdel` vs `usermod`)이라 **같을 필요 없음** — **외울 때는 명령별로** `-r`=recursive, `-L`=Lock, `-U`=Unlock.

### 2-5
**상황:** 사용자 **`test`** 비밀번호만 바꾼다. (PDF slide 13)

```bash
passwd ______
```

**정답:** `test`

**해설:** root가 `# passwd test` 실행. 다음 로그인 시 바꾸게 하려면 **`passwd -e test`**.

### 2-6
**상황:** 사용자 **`test`** 의 **기본 쉘**을 `/bin/csh`로. (PDF slide 14 · chsh)

```bash
chsh ______ /bin/csh test
```

**정답:** `-s`

**해설:** 한 줄씩 풀면 아래와 같습니다.

| 용어 | 뜻 |
|------|-----|
| **기본 쉘(default shell)** | 그 사용자가 **로그인했을 때 자동으로 뜨는 명령 입력 프로그램** (보통 bash). `/etc/passwd` 마지막 필드에 경로로 저장됨 |
| **`/bin/csh`** | **C shell** 이라는 쉘 프로그램 **파일의 전체 경로**. `bash` 대신 **csh로 로그인**하게 바꾸는 예 |
| **`chsh`** | **ch**ange **sh**ell — **기본 쉘을 바꾸는** 명령 (PDF slide 14) |
| **`-s`** | **s**hell — “**이 경로의 쉘**로 바꿔라”는 옵션 |

```bash
chsh -s /bin/csh test
#      ↑    ↑        ↑
#      -s   쉘경로   사용자
```

- **`test`만** `csh`로 로그인하게 바꿈 · **`/bin/bash` → `/bin/csh`**
- **`csh`만** 쓰면 안 됨 → **`/bin/csh`처럼 전체 pathname** (PDF: full pathname for shell)

**비유:** 기본 쉘 = “로그인하면 항상 열리는 **앱**” · `chsh -s` = “그 앱을 **bash → csh**로 교체”.

### 2-7 (history 2.sh)
**상황:** 컴파일한 **`myMain`** 을 실행 가능하게.

```bash
gcc main.c -o myMain
chmod ______ myMain
./myMain
```

**정답:** `+x` (또는 `u+x`)

**해설:** **`gcc`** = **G**NU **C** **C**ompiler — C 소스(`.c`)를 **실행 파일**로 **컴pile(컴파일)** 하는 명령. (`history 2.sh` 24~26행)

| 부분 | 의미 |
|------|------|
| **`gcc main.c`** | `main.c` 소스를 컴파일 |
| **`-o`** | **o**utput — 만들 **실행 파일 이름** 지정 |
| **`myMain`** | `-o` 뒤 이름 → **`myMain`** 이라는 실행 파일 생성 (없으면 기본 **`a.out`**) |
| **`chmod +x myMain`** | 실행 권한 **`x`** 추가 (`+x` = all에 execute) |
| **`./myMain`** | 현재 폴더의 `myMain` **실행** |

**`-o` 없으면:** `gcc main.c` → **`a.out`** 만 생김 (`history 2.sh`의 `gcc -c`, `./a.out` 흐름).

**시험·수업에서 자주 나오는 gcc 옵션 (참고):**

| 옵션 | 축약 | 의미 |
|------|------|------|
| **`-o`** | **o**utput | 실행 파일 **이름** |
| **`-c`** | **c**ompile | **`.o` 오브젝트만** 만들고 링크는 안 함 (`history 7.sh`) |
| **`-g`** | **g**debug | **gdb** 디버깅용 정보 포함 (`history 9.sh`) |
| **`-Wall`** | **W**arning **all** | **경고** 메시지 더 출력 (`history 8.sh`) |

08·권한 문제 **핵심**은: 컴파일 → **`chmod +x`** → **`./`** 실행.

### 3-3 (umask · history 2.sh)
**상황:** umask 설정 후 파일·디렉터리 생성.

```bash

```

**문제:** (빈칸) 위 두 명령 **직후** `a.txt`·`tempDir`의 **8진 권한**(강의 빼기법)은?

**정답:** **`a.txt` → 622** · **`tempDir` → 733**

**해설:** **왜 파일 666 · 폴더 777인가?**

Linux **새로 만들 때**의 **최대(기본) 권한**이 다릅니다 (umask **적용 전**).

| | 기본 8진 | 기호 | 이유 |
|---|----------|------|------|
| **일반 파일** | **666** | `rw-rw-rw-` | 새 파일은 **실행(x) 없이** — 보안(실수로 실행 파일 X). 읽기·쓰기만 |
| **디렉터리** | **777** | `rwxrwxrwx` | 폴더는 **들어가려면 x**, **목록 보려면 r**, **안에 파일 만들려면 w** — **x가 필수** |

**폴더의 `x`:** 파일의 “프로그램 실행”과 **다름** → **cd로 들어가기·경로 통과(search)** 권한.  
그래서 폴더 기본에 **x가 포함(777)** · 파일 기본은 **x 없음(666)**.

**umask 0044 적용 (강의 빼기):**
- `a.txt`: **666 − 044 = 622** (`rw- -w- -w-`)
- `tempDir`: **777 − 044 = 733** (`rwx-wx-wx`)

(표준 계산: `666 & ~umask`, `777 & ~umask` — 결과 동일)

## 유형 6. 명령 출력 예측

> **`ls -l`·권한 문자열·umask 결과** (공지: outcomes)

---

### 6-1
**상황:** `Lecture/ShellScriptProgram/test` 첫 줄

```
drwxrwxr-x 2 hwj hwj 4096 May 20 09:51 .
```

**문제:**  
(1) **`d`** 의미?  
(2) **user** 권한 기호?  
(3) **other** 권한 기호?

**정답:** (1) **디렉터리** (2) **`rwx`** (3) **`r-x`**

**해설:** 한 줄 구조:

```
drwxrwxr-x  2  hwj  hwj  ...
│└┬┘└┬┘└┬┘      │    │
│ u  g  o        │    └── 그룹 **이름** (group)
│                └── 소유자 **이름** (user)
└ d = directory
```

| 글자 | 뜻 | 이 줄에서 |
|------|-----|-----------|
| **u** (user) | **소유자** — 파일 **주인** | `hwj` → **`rwx`** |
| **g** (group) | **그룹** — 소유자와 **같은 그룹**에 속한 **다른 사용자들** | 두 번째 `hwj`(그룹명) → **`rwx`** |
| **o** (other) | **그 밖의 사람** — owner·group **아닌** 사용자 | **`r-x`** |

**group은 언제 쓰이나?**
- Linux는 사용자를 **그룹(팀)** 으로 묶음 (예: `students`, `staff`, 같은 `hwj` 그룹)
- **`ls -l`의 4번째·5번째 열** = **owner / group 이름**
- 권한 **가운데 3칸(`g`)** = “**나(주인) 말고, 같은 그룹 멤버**에게 줄 권한”
- 예: `rwxrwxr-x` → 그룹 멤버도 **읽·쓰·들어가기** 가능, others는 **읽기+실행만**

**09.md**에서 `/etc/group`, `chgrp`, `groups` 명령으로 **그룹 관리**를 더 다룸. `chmod g+w` = **그룹**에 쓰기 추가.

```
-rwxrw-r-- 1 hwj hwj 737 May 20 09:46 myshell1.sh
```

**문제:** (1) 8진 권한? (2) **group**은 **쓰기** 가능한가? ( O / X )

**정답:** (1) **764** (2) **O**

**해설:** u=rwx(7) g=rw-(6) o=r--(4). group **`w`** 있음.

### 6-7 (종합 표)
**상황:** 아래 `ls -l` 두 줄만 주어짐.

```
-rw-rw-r-- 1 user1 staff 100 Jun  5 10:00 report.txt
drwx--x--x 2 user1 staff 4096 Jun  5 10:01 secret/
```

**문제:** 표를 채우시오.

| 대상 | 타입(파일/디렉터리) | other가 read 가능? | other가 cd 가능? |
|------|---------------------|:------------------:|:----------------:|
| `report.txt` | | | |
| `secret/` | | | |

**정답:**  
| | | | |
| report.txt | **파일** | **O** (`r--`) | **—**(cd는 디렉터리만) |
| secret/ | **디렉터리** | **X** (`--x`만, read 없음) | **O** (`x` 있음) |

**해설:** 디렉터리 **`--x`**: **이름으로 cd는 가능**할 수 있으나 **`ls` 목록(read)은 불가** — 시험은 **other의 r/x 유무** 구분.

### 6-8
**상황:** PDF slide 8 — `/etc/skel` 목록

```
drwxr-xr-x 2 root root 4096 ... .
-rw-r--r-- 1 root root   33 ... .bash_logout
-rw-r--r-- 1 root root  176 ... .bash_profile
-rw-r--r-- 1 root root  124 ... .bashrc
```

**문제:** 새 사용자 HOME에 **복사되는 bash startup 파일** 이름 **3개**?

**정답:** **`.bash_logout`** · **`.bash_profile`** · **`.bashrc`**

**해설:** `useradd` 시 **`/etc/skel` → `/home/로그인명/`** 복사 (PDF slide 8).

**07.md와 질문 정리 — 질문 맞음:**

| 구분 | 파일 | **언제** 실행? |
|------|------|----------------|
| **시작(startup)** | `/etc/profile` → `.bash_profile` / `.bash_login` / `.profile` → (보통) `.bashrc` | **로그인·쉘 시작** (07.md) |
| **종료(logout)** | **`.bash_logout`** | **로그아웃·login shell 종료** 직전 |

**`.bash_logout`은 startup 순서에 **없음** — **나갈 때** 한 번 실행되는 **종료 스크립트** (예: `echo "Goodbye"`).

**왜 skel에 3개만?**
- **`.bash_profile`** + **`.bashrc`** = **시작**용 (07.md와 연결)
- **`.bash_logout`** = **끝날 때**용 — **시작 순서와 별개**
- **`.bash_login`**, **`.profile`** = `.bash_profile` **대안**(2nd/3rd Try) — **skel 템플릿에 안 넣을 수도** 있음 (배포판마다 skel 구성 다름)

**한 줄:** 07.md = **들어올 때** 읽는 순서 · 6-8 = **useradd가 복사하는 skel 파일 목록** · **`bash_logout` = 나갈 때** (시작 순서 아님).
