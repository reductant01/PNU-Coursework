### 1-2
**문제:** **GID**(**G**roup **ID**)는 그룹마다 하나씩 있는 **고유 숫자**이다. ( O / X )

**정답:** **O**

**해설:** **GID** = **G**roup **ID** — 그룹마다 **고유 숫자**. UID(사용자 번호)와 짝.

**`/etc/passwd` 7필드 (암기 — 08.md 복습):**

```
login : password : UID : GID : comment : HOME : shell
```

| 순서 | 필드 | 예 (`test:x:504:504:…:/home/test:/bin/bash`) |
|------|------|-----------------------------------------------|
| 1 | **login** | 로그인 **이름** (`test`) |
| 2 | **password** | **`x`** = 비밀번호는 **`/etc/shadow`** |
| 3 | **UID** | **U**ser **ID** — 사용자 **번호** (`504`) |
| 4 | **GID** | **G**roup **ID** — **기본 그룹** 번호 (`504`) ← **이 문제** |
| 5 | **comment** | 이름·부서 등 **설명** (GECOS) |
| 6 | **HOME** | **홈 디렉터리** (`/home/test`) |
| 7 | **shell** | **기본 쉘** (`/bin/bash`) |

**암기:** **이름·pw·UID·GID·설명·HOME·shell** (7개)

- **4열 GID** = passwd의 **기본 그룹** · **`/etc/group`** = 그룹 **전체 목록** + **멤버** (09 2-3)
- **`usermod -G shared`** = **보조 그룹** 추가 (4열 **기본 GID**와 **다름**)

### 1-4
**문제:** **시스템 그룹**은 보통 GID **500 미만**, **일반 사용자 그룹**은 **500부터** 할당한다. ( O / X )

**정답:** **O**

**해설:** Linux는 **GID 숫자 구간**을 나눠 씁니다 — **작은 번호 = OS·서비스용**, **500 이상 = 사람(일반 사용자)용**.

| 구분 | GID 범위 | 누가 쓰나 | `/etc/group` 예 |
|------|----------|-----------|-----------------|
| **시스템 그룹** | **0 ~ 499** (**500 미만**) | `root`, `bin`, `daemon`, `mysql` … OS·프로그램 설치 시 **자동 생성** | `root:x:0:` · `daemon:x:2:…` · `mysql:x:27:` |
| **일반 사용자 그룹** | **500부터** | `useradd`로 만든 **사람 계정**·`groupadd shared` 같은 **우리가 만든 그룹** | `rich:x:500:` · `shared:x:505:rich,test` |

**“500 미만”** = GID 숫자가 **0, 1, 2, … 499** 인 그룹 → **시스템이 예약**해 둔 구간.  
**“500부터”** = **504, 505** … 처럼 **큰 번호** → **수업·실습에서 만드는 사용자/공유 그룹**.

**비유:** **0~499번 사물함 = 학교(시스템) 전용** · **500번부터 = 학생(사용자) 사물함**.

시험: **500 미만 = system · 500+ = user group** 만 기억하면 됨.

### 1-6
**문제:** **`ls -l`** 에서 **공백으로 나눈 4번째 필드**는 **그룹 이름**(group)이다. ( O / X )

**정답:** **O**

**해설:** **`ls -l`** 한 줄 — **공백으로 나눈 필드** 순서 (PDF slide 5~6):

```
-rw-rw-r--   1   rich   rich    50   Sep 13 07:49   file1.gz
   필드1     2     3      4      5      필드6~8         9
                  owner group  size
```

| 필드 | 의미 | 예 |
|------|------|-----|
| **1** | **권한** 10칸 (`-`/ `d` + u·g·o rwx) | `-rw-rw-r--` |
| **2** | **링크 수** | `1` |
| **3** | **owner** — 소유자(user) 이름 | `rich` |
| **4** | **group** — 소유 그룹 이름 ← **이 문제** | `rich` |
| **5** | **크기**(byte) | `50` |
| **6~8** | **날짜·시간** | `Sep 13 07:49` |
| **9** | **파일·폴더 이름** | `file1.gz` |

**정리:** 권한을 **한 덩어리(필드1)** 로 세면 → **group = 4번째 필드** (맞음).  
**헷갈림:** “5번째”라고 적힌 옛 표기는 **size(크기)** — **group 아님**.

**권한 10칸 안의 g:** **그룹에게 줄 rwx** (필드4 **그룹 이름**과 **다름**) — 08.md.

**`chown`/`chgrp` 후:** 필드 **3(owner)·4(group)** 만 바뀜 → 유형 5.

### 1-7
**문제:** **`chgrp`** 는 파일 **소유 그룹만** 바꾸고, **`chown`** 은 **소유자(user)** (및 필요 시 그룹)를 바꾼다. ( O / X )

**정답:** **O**

**해설:**

| 명령 | 축약 | 뜻 |
|------|------|-----|
| **`chgrp`** | **ch**ange **gr**oup | 파일 **소유 그룹(group)만** 변경 |
| **`chown`** | **ch**ange **own**er | 파일 **소유자(owner)만** 또는 **owner+group** 변경 |

**예 (PDF slide 11~12):**
- `chgrp shared newfile` → **group**만 `shared` · owner **그대로**
- `chown dan newfile` → **owner**만 `dan` · group **그대로**
- `chown dan.dan newfile` → owner **`dan`** + group **`dan`**
- `chown .rich newfile` → owner **그대로** · group만 **`rich`**

**`ls -l`:** `chgrp`/`chown` 후 **필드3(owner)·필드4(group)** 이름이 바뀜 (1-6).

### 1-8
**문제:** **`chmod g+s`** 는 디렉터리에 **SGID**를 설정해, 그 안에 **새로 만든 파일**이 **디렉터리 그룹**을 기본 그룹으로 쓰게 할 수 있다. ( O / X )

**정답:** **O**

**해설:** PDF slide 13~15. **755 같은 rwx와 별개**인 **특수 비트** — 이 문제는 **SGID(`g+s`)**.

**SUID vs SGID — 뭐가 다른가? (1-9와 짝)**

| | **SUID** (`u+s`) | **SGID** (`g+s`) ← **이 문제** |
|--|------------------|--------------------------------|
| 붙는 위치 | **user** triplet | **group** triplet |
| 8진 | **4** | **2** |
| 주로 어디 | **실행 파일** (`/bin/ping`) | **디렉터리** (공유 폴더) |
| **하는 일** | **실행할 때** → 파일 **owner** 권한으로 동작 | **파일 만들 때** → **폴더 group**을 새 파일에 **물려줌** |
| 시험 한 줄 | “**돌릴 때** owner 권한” (1-9) | “**만들 때** 폴더 group 상속” (1-8) |

**`s`는 user/group의 x 자리에 붙나? — 맞음 (표시 위치):**

| 비트 | `ls -l`에서 `s` 나오는 곳 | x와 관계 |
|------|---------------------------|----------|
| **SUID** | **user** execute 자리 (`r-s…`) | **`s`** = x **있음** + SUID · **`S`** = x 없음 + SUID만 |
| **SGID** | **group** execute 자리 (`…rws…`) | **`s`** = x **있음** + SGID · **`S`** = x 없음 + SGID만 |

→ **어느 triplet에 특수 비트를 걸었는지**가 SUID/SGID 구분. **`s`/`S`는 그 자리의 x 표시를 대체**할 뿐, “SGID = group x만 켜면 된다”는 뜻 **아님**.

**`chmod g+s`:** **g**roup + **s**etgid — **SGID만 켬** (기존 rwx는 그대로). 8진 **`2755`** 는 SGID+755 **한 번에** 줄 때 쓰는 **별 방법** (필수 아님).

**이 문제 동작 (`shared` 폴더):**

| | SGID 없음 | **`chmod g+s`** |
|--|-----------|-----------------|
| `rich`가 `touch f` | group = `rich` (본인 기본) | group = **`shared`** (폴더 그룹) |

**sticky** (`o+t`, 8진 **1**): `/tmp` — 남의 파일 삭제 방지 (1-10).

→ 공유 폴더 **세트:** `chgrp shared` + **`chmod g+s`** + **`umask 002`** (slide 15).

### 1-9
**문제:** **SUID**는 파일 실행 시 **파일 소유자(owner) 권한**으로 프로그램이 돌아가게 한다. ( O / X )

**정답:** **O**

**해설:** PDF slide 13. **SUID** = **S**et **U**ser **ID** — **실행 파일** 전용.

**SUID vs SGID (1-8과 짝):**

| | **SUID** (이 문제) | **SGID** (1-8) |
|--|-------------------|----------------|
| 축약 | **S**et **U**ser **ID** | **S**et **G**roup **ID** |
| 8진 | **4** | **2** |
| `chmod` | `u+s` | `g+s` |
| 대상 | 주로 **실행 파일** | 시험에선 주로 **디렉터리** |
| 효과 | 실행 시 **파일 owner** 권한으로 동작 | 디렉터리 안 **새 파일**이 **폴더 group** 상속 |

**왜 필요?** — 일반 사용자는 root 전용 작업(예: ping)을 못 함 → **SUID**로 “실행할 때만 owner(root) 권한” 부여.

**예:** `/bin/ping` — `r-sr-sr-x` · 8진 **`4755`** (= **4** + 755)

```
r-sr-sr-x
  ↑
user execute 자리 = s → SUID 켜짐 (x 있음 + SUID)
```

**`s` 표기:** user triplet의 **x 자리**에 SUID가 켜지면 **`s`** (x 없으면 **`S`**).

### 1-10
**문제:** **sticky bit**는 “프로세스 끝난 뒤에도 **파일이 메모리에 남는다**”는 뜻이다. ( O / X )

**정답:** **O**

**해설:** PDF slide 13. **특수 비트 3번째** — SUID(4)·SGID(2) 다음.

**sticky bit 한 줄:**

| 항목 | 내용 |
|------|------|
| 이름 | **sticky bit** (끈적 sticky = “붙어 있다”) |
| 8진 | **1** (앞자리) |
| `chmod` | **`o+t`** — **o**ther triplet에 **t** 추가 |
| 8진 예 | `1777` = **1**(sticky) + **777** |

**이 문제(O) — PDF·교재 정의 (옛날, 실행 파일):**

> 프로세스가 **끝난 뒤에도** 실행 파일 **텍스트(코드)가 메모리에 남아** 다음 실행이 빨라진다.

- 시험 O/X는 **이 한 줄 정의**를 묻는 경우가 많음 → **O**.
- 요즘 Linux에서는 실행 파일 sticky는 **거의 안 씀** — 이름·개념만 알면 됨.

**실무에서 더 자주 보는 뜻 (디렉터리 — `/tmp`):**

디렉터리에 sticky가 켜지면 → **폴더 안 파일을 지우거나 이름 바꿀 수 있는 사람**이 **그 파일 owner**(또는 root) **뿐**.

| | sticky **없음** | sticky **있음** (`o+t`) |
|--|-----------------|-------------------------|
| `/tmp` 같은 공용 폴더 | w 있으면 **남의 파일도** 삭제 가능 | **본인 파일만** 삭제·이름 변경 |

→ 여러 사용자가 **같은 디렉터리에 쓰기**할 때, **남의 파일을 못 지우게** 막는 용도.

**`ls -l`에서 `t`:**

others triplet의 **x 자리**에 sticky가 켜지면 **`x` 대신 `t`**.

```
drwxrwxrwt   ← /tmp 예 — 마지막 other execute 자리 = t
        ↑
   sticky on 디렉터리
```

- **`t`** (소문자): x **있음** + sticky  
- **`T`** (대문자): x **없음** + sticky만  

**왜 SUID·SGID는 `s`, sticky는 `t`?**

| 표시 | 어디 | 글자 | 이유 |
|------|------|------|------|
| **`s`** | user **x** 자리 | **s** | **S**et **U**ser **ID** — “**set**”의 **s** |
| **`s`** | group **x** 자리 | **s** | **S**et **G**roup **ID** — 같은 “**set ID**” 계열이라 **같은 s** |
| **`t`** | other **x** 자리 | **t** | **sticky** bit — 이름 **sticky**의 **t** (set ID와 **다른 종류** 비트) |

- **`chgrp`/`chown` 같은 명령 축약어가 아님** — `ls -l`이 **x 자리 하나**에 “특수 비트 켜짐”을 표시하는 **Unix 관례**.
- **SUID·SGID**는 둘 다 “**ID를 set한다**”는 **같은 계열** → 표시도 **`s` 하나** · **어느 triplet인지**(user/group)로 구분.
- **sticky**는 “메모리에 **붙어 남는다**”는 **별개 개념** → **`t`** 로 구분 (`chmod o+**t**` 와도 맞음).
- **대·소문자 규칙은 s·t 공통:** 소문자 = x **있음** · 대문자 = x **없음** (`s`/`S`, `t`/`T`).

```
rwsr-sr-t   ← 예시 (각 triplet execute 자리)
  s   s   t
 SUID SGID sticky
```

**1-8 표와 짝:**

| 비트 | 8진 | 기호 | 시험·실무 포인트 |
|------|-----|------|------------------|
| SUID | 4 | `u+s` | 실행 파일 → **owner** 권한 (1-9) |
| SGID | 2 | `g+s` | 디렉터리 → **폴더 group** 상속 (1-8) |
| **sticky** | **1** | **`o+t`** | 디렉터리 → **남의 파일 삭제 방지** (`/tmp`) |

### 1-11
**문제:** **`usermod -G shared rich`** 는 **`rich`를 `shared` 그룹 멤버**로 만든다. (PDF 예) ( O / X )

**해설:** PDF slide 4.

**이 명령이 하는 일 (한 줄):**

`rich` 사용자를 **`shared` 그룹 멤버 목록에 이름을 적어 넣는다** → **O**.

**순서대로:**

```bash

```

**`-G` 뜻:**

| | |
|--|--|
| **`-G`** | **G**roups — **그룹 멤버십(소속)** 을 바꿀 때 쓰는 옵션 |

**어디가 바뀌나?** — **`/etc/group`** 파일 **마지막 칸**(멤버 목록):

```
변경 전:  shared:x:505:
변경 후:  shared:x:505:rich,test
                        ↑ rich 이름이 여기 추가됨
```

**`groupadd`와 짝:** `groupadd` = **빈 그룹 생성** · `-G` = **그 그룹에 사람 추가**.

**`-g`(소문자)는?** — **있긴 함** (`usermod -g` = **기본 그룹**만 바꿈 · `/etc/passwd` 4열).  
**이 PDF·문제는 `-G`(대문자)** — **`shared` 멤버로 추가**하는 예. 시험에선 **`-G` = 보조 그룹 멤버 추가**만 기억하면 됨.

### 2-10
**상황:** 공유 디렉터리 **`testdir`** 에 **SGID** 설정.

```bash
chmod ______ testdir
```

**정답:** `g+s`

**해설:** PDF slide 14~15. `ls -l` → `drwxrwsr-x` — group **x** 자리 **`s`** = SGID.

**특수 비트 3종 복습 (`chmod` 기호 — 1-8~1-10):**

| 명령 | 대상 | 축약 | 8진 | `ls -l` 표시 | 하는 일 |
|------|------|------|-----|--------------|---------|
| **`chmod u+s`** | **u**ser triplet | **S**UID | **4** | user **x** → **`s`** | **실행 파일** — **owner** 권한으로 실행 (ping) |
| **`chmod g+s`** | **g**roup triplet | **S**GID | **2** | group **x** → **`s`** | **디렉터리** — 새 파일·폴더 **폴더 group** 상속 ← **이 문제** |
| **`chmod o+t`** | **o**ther triplet | **sticky** | **1** | other **x** → **`t`** | **디렉터리** — **남의 파일** 삭제·이름 변경 방지 (`/tmp`) |

**이 문제가 묻는 것:** **SGID 비트만** 켜기 → 정답 **`g+s` 한 가지**.

**`g+s` vs `2755` — 헷갈리는 점:**

| | **`chmod g+s testdir`** | **`chmod 2755 testdir`** |
|--|-------------------------|--------------------------|
| SGID | **켜짐** | **켜짐** (앞자리 **2**) |
| rwx 권한 | **기존 권한 유지** + SGID만 추가 | **755로 통째로 덮어씀** (rwxr-xr-x) |
| 이 문제 | **정답** — “SGID 설정”만 물음 | **필수 아님** — SGID+권한을 **한 번에** 줄 때 쓰는 **다른 방법** |

→ **`2755`일 필요 없음.** group·user에 **x만** 있으면 된다(X) — 디렉터리 협업엔 보통 **rwx**(특히 group **w**)도 따로 필요하고, **`g+s`는 group 상속만** 담당.

**최소 vs PDF 레시피 (slide 15):**

```
chgrp shared testdir      # ① 폴더 group = shared
chmod g+s testdir         # ② SGID만 (이 문제) — rwx는 안 바꿈
# (보통) chmod 775 testdir  ← 들어가기·파일 만들기용 — SGID와 별개
```

**`2755`는** “SGID + 권한을 755로 맞춤”을 **한 줄**로 하고 싶을 때의 **편의 예**일 뿐, **`g+s`와 완전 동일한 명령이 아님.**

### 2-12
**상황:** **`chown`** 으로 **하위 디렉터리·파일까지** 소유자 변경.

```bash

```

**정답:** `-R`

**해설:** PDF slide 12. **`-R`** = **R**ecursive — **폴더 안 하위까지** owner 변경.

```bash

```

**왜 `userdel`은 `-r`(소문자), `chown`은 `-R`(대문자)?**

| | **`userdel -r`** (08.md) | **`chown -R`** (이 문제) |
|--|--------------------------|--------------------------|
| 뜻 | **r**ecursive — HOME·메일까지 **삭제** | **R**ecursive — 하위까지 **소유자 변경** |
| 대소문자 | **소문자 `-r`** | **대문자 `-R`** |

→ **Unix/Linux는 “재귀 옵션이 항상 -r” 같은 전역 규칙이 없음.**  
**명령마다 옵션 문자가 따로 정해져 있음** — `man userdel` / `man chown` 기준으로 **외울 때는 명령별로** 기억.

**비슷한 예 (전부 같지 않음):**

| 명령 | 재귀 옵션 |
|------|-----------|
| `userdel -r` | 소문자 **`-r`** |
| `rm -r` | 소문자 **`-r`** |
| `chown -R` | 대문자 **`-R`** |
| `grep -R` | 대문자 **`-R`** (05.md) |

**시험:** PDF·문제에 나온 **그 명령 그대로** — `chown` 재귀 = **`-R`**.

### 2-13
**상황:** 그룹 **협업**용 — 새 파일이 그룹 **쓰기** 가능하도록 umask.

```bash

```

**정답:** `002` (또는 `0002`)

**해설:** PDF slide 15. **`umask 002`** = 강의·시험 **표준 레시피**.

**계산:** `666 − 002 = 664` → 새 파일 **`rw-rw-r--`** (group **r+w** 유지).

**“group w만 켜지면 되니까 `002` 아니어도 되지?” — 맞는 말 (수학적으로):**

umask **가운데 자리 = 0** 이면 group **w**는 안 막힘 → **`000`·`001`·`007` …** 도 group w 가능.

| umask | 새 파일 (666 기준) | group w? | others w? |
|-------|-------------------|----------|-----------|
| **`022`** | **644** `rw-r--r--` | **X** (막힘) | X |
| **`002`** | **664** `rw-rw-r--` | **O** | X (others 읽기만) |
| **`000`** | **666** `rw-rw-rw-` | O | **O** (너무 열림) |

→ **group w 하나만** 보면 경우의 수 많음. **시험·PDF는 `002`** — **664**로 “팀은 쓰고, others는 읽기만”이라 **딱 맞는 값**.

**디렉터리:** `777 − 002 = 775` (`rwxrwxr-x`) — group이 **폴더 안에 파일 생성** 가능.

**정리:** 최소 조건 = umask가 **group w를 막지 않을 것** · **정답 `002`** = slide 15 **협업 세트** (`g+s` + `chgrp shared`와 짝).

### 3-1 (PDF · groupadd + usermod)

**정답:** `-G` / `-G`

**해설:** PDF slide 4.

**`-G` / `-G`:** `rich`·`test`를 **`shared` 그룹 멤버**로 추가 (1-11).  
→ **`/etc/group` 4번째 필드(멤버 목록)** 에 이름이 **추가**됨.

**`/etc/group` 한 줄 = 4필드 (2-3):**

```
그룹이름 : password : GID : 멤버목록
shared   :    x     : 505 : rich,test
   ①          ②       ③        ④
```

**`tail` 역할 — 멤버 목록만 뽑는 명령이 아님:**

| | |
|--|--|
| **`tail`** | 파일 **맨 끝 몇 줄**(기본 10줄)을 **통째로** 출력 |
| **`tail /etc/group`** | `/etc/group` **끝쪽 줄들**을 보여 줌 — **한 줄마다 ①~④ 전부** 포함 |

→ **④ 멤버 목록만** 따로 보여 주는 게 **아님**.  
**한 줄 전체**가 나오고, 그중 **마지막 칸**에 `rich,test` 같은 **멤버 목록**이 붙어 있음.

**PDF에서 `tail` 쓰는 이유:** `groupadd`로 **새 그룹**을 만들면 보통 파일 **아래쪽**에 한 줄 추가됨 → **끝부분만** 보면 `shared:…:rich,test` **한 줄로** 확인 가능 (**확인용**).

**기대 출력 (예):**

```
shared:x:505:rich,test
```

**멤버만 보고 싶으면** `tail`이 아니라 예: `grep shared /etc/group` → 그 줄의 **④번째 필드**를 보면 됨.

**`ls -l` 필드 복습 (1-6):** 공백 기준 **9필드**

```
-rw-rw-r--   1   rich   shared   0   …   testfile
   ①        ②    ③      ④     ⑤  ⑥~⑧    ⑨
  권한     링크 owner  group  크기  날짜   이름
```

| 필드 | 의미 | **이 문제 `testfile`** |
|------|------|------------------------|

| **4** | **group** — 소유 그룹 | **`shared`** ← **정답** (SGID 상속) |
| **5** | 크기(byte) | `0` |
| **6~8** | 수정 날짜·시간 | … |
| **9** | 파일 이름 | `testfile` |

**먼저 구분 — owner(③) vs group(④):**

| `ls -l` | 이 문제에서 | slide 15 |
|---------|-------------|----------|
| **필드3 owner** | **물어보지 않음** (위 표 ③) | **`rich`** |
| **필드4 group** | **`rich` vs `shared`** ← **이 문제** (④) | **`shared`** |

**owner가 `rich`인 이유 (문제 밖·PDF 맥락):**  
`touch testfile` 을 친 사람 = **지금 쉘에 로그인한 사용자**. slide 4~15 예시가 **`rich`** 라서 owner는 **`rich`** — **group을 고르는 문제와 별개**.

**group이 `shared`인 이유 (정답):**

| SGID **없으면** | SGID **있으면** (`chgrp shared` + `g+s`) |
|-----------------|------------------------------------------|
| 새 파일 group = **`rich`** (만든 사람 **기본 그룹**) | 새 파일 group = **`shared`** (**폴더 group** 상속) |

→ **`rich`/`shared` 중 고르라** = “기본 그룹 vs SGID 상속” — **`shared`**.
