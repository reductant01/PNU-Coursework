### 1-5
**문제:** **`df`**는 파일시스템(장치) **여유 공간**, **`du`**는 **디렉터리·파일 사용량**을 본다. ( O / X )

**정답:** **O**

**해설 — `df` vs `du` 출력 차이 (`5-2` · `5-3` · `5-5`):**

| | **`df`** | **`du`** |
|---|----------|----------|
| **줄임** | **d**isk **f**ree | **d**isk **u**sage |
| **무엇을 보나** | **파일시스템(장치·파티션) 전체** | **지정한 디렉터리·파일**이 차지하는 용량 |
| **단위** | **마운트된 디스크** (`/`, `/media/disk` …) | **경로** (`~`, `*`, `./docs` …) |

**`df -h` 출력 형태** — **장치(파티션)마다 한 줄:**

```
Filesystem      Size  Used Avail Use% Mounted on
/dev/sda1       100G  40G  55G  43% /
```

→ **여유·사용률** · **어디에 붙었는지(Mounted on)** (`5-2` `5-3`).

**`du` 출력 형태** — **지정 경로 아래 항목마다** (또는 `-s`로 **한 줄 합계**):

```
du ~              # 하위 폴더마다 여러 줄 (블록 수 + 경로)
du -sh ~          # 홈 전체 합계 한 줄 (예: 1.2G /home/user)
du -sh *          # 현재 폴더 각 항목 한 줄씩 (`2-8`)
```

**한눈에 비교:**

| 질문 | 쓸 명령 |
|------|---------|
| **이 디스크에 여유가 얼마나?** | `df -h` |
| **이 폴더가 용량을 얼마나 쓰나?** | `du -sh 경로` |
| **현재 폴더에서 뭐가 큰가?** | `du -sh * \| sort -hr` (`3-4`) |

→ **`df`** = 파티션 **전체** · **`du`** = **특정 경로** 아래 파일들이 **실제로 차지한** 크기.

### 1-10 (`grep` · `egrep` · `fgrep` · `.` 패턴)
**상황:** `Lecture/file3`:

```
1234 567 800
123 9978.

123 456
```

**문제:** `grep "." file3` 과 `fgrep "." file3` 은 **같은 줄만** 출력한다. ( O / X )

**정답:** **X**

**해설 — 세 가지 비교 (`history 5.sh` 49~52 · `2-26`):**

| 명령 | 동일 표현 | 옵션 줄임말 | 패턴 해석 |
|------|-----------|-------------|-----------|
| **`grep`** | (기본) | — | **기본 정규식** (BRE) |
| **`egrep`** | **`grep -E`** | **E** = **E**xtended | **확장 정규식** (ERE) · `\|` `()` `+` 등 |
| **`fgrep`** | **`grep -F`** | **F** = **F**ixed strings | **고정 문자열** · `.` `*` 등 **메타문자 안 씀** |

**`-E` / `-F` 헷갈리기 쉬운 것:**

| 옵션 | 뜻 | 아닌 것 |
|------|-----|--------|
| **`-E`** | **E**xtended · **확장** 정규식 (`egrep`) | **`-e`** (패턴 **하나** 지정 · `2-13`) |
| **`-F`** | **F**ixed · **고정** 문자열 (`fgrep`) | 정규식 아님 |

**이 문제 — `file3` 에서 `"."` 패턴:**

| 명령 | `.` 의미 | 출력 줄 수 | 출력 |
|------|----------|------------|------|
| **`grep "." file3`** | **임의 한 글자** | **3줄** | `1234 567 800` / `123 9978.` / `123 456` |
| **`egrep "." file3`** | **임의 한 글자** (확장 regex에서도 동일) | **3줄** | 위와 **같음** |
| **`fgrep "." file3`** | **점(.) 글자 그대로** | **1줄** | `123 9978.` **만** |

→ 문제는 **`grep` vs `fgrep`** 만 묻지만 · **`egrep` 도 `grep` 과 같이 3줄** → **`fgrep` 만 다름** → **X** (`6-7`).

**언제 `egrep` 이 `grep` 과 달라지나** (이 문제 밖):

**이스케이프(escape)란?** — 특수문자 앞에 **`\`(백슬래시)** 를 붙여 **“이 글자를 다르게 해석해라”**고 알려 주는 것.

- **`\|`** = `|` 앞에 `\` → grep 기본 정규식에서 **OR** 로 씀
- **`\.`** = `.` 앞에 `\` → “아무 글자”가 아니라 **점(.) 글자** 로 씀 (`fgrep` 과 비슷한 효과)

`file1` (`two`, `four` 있는 파일) 예:

| 명령 | `file1` 출력 | 이유 |
|------|--------------|------|
| `grep 'tw\|fo' file1` | `two` / `four` | **`\|`** 로 OR |
| `grep 'tw|fo' file1` | **(없음)** | 기본 `grep` 에서 `\|` 없는 `\|` 는 OR 로 **안 됨** |
| `egrep 'tw|fo' file1` | `two` / `four` | 확장 정규식에서 **`|`** 가 바로 OR |

→ **이스케이프** = `\`로 메타문자 의미를 바꿈 · **`grep`은 `\|`** · **`egrep`은 `|`** 만 써도 OR.

**한 줄 요약:**

```bash
grep "." file3     # 정규식 · 한 글자라도 있는 줄 (3줄)
egrep "." file3    # 확장 정규식 · 이 경우 grep 과 같음 (3줄)
fgrep "." file3    # 고정 문자열 · 점(.) 있는 줄만 (1줄)
```

### 1-11
**문제:** `grep [tf] file1` 과 `grep tf file1` 은 **같은 결과**다. ( O / X )

**정답:** **X**

**해설 — `[tf]` vs `tf` (`file1` 예):**

| 명령 | `file1` 출력 | 패턴 의미 |
|------|--------------|-----------|
| **`grep [tf] file1`** | `two` `three` `four` `five` | **`t` 또는 `f` 글자 하나** |
| **`grep tf file1`** | **(없음)** | **`t` 바로 뒤 `f`** 가 **연속**으로 붙은 문자열 |

**`[tf]` 가 OR처럼 보이는 이유 — 쉘 실행문이 아님:**

- **`[]` 는 grep 정규식 문법** (문자 클래스 · character class).
- **`[tf]`** = “이 위치에 **`t` 또는 `f` 중 한 글자**” · 줄 **어디서든** 그 글자가 있으면 매칭.
- 쉘이 `[]` 를 **실행문·명령**으로 해석하는 것과 **무관** — 따옴표 없어도 `[tf]` 는 **grep에 넘어가는 패턴**일 뿐.

```
two    → t 있음 ✅    three → t 있음 ✅
four   → f 있음 ✅    five  → f 있음 ✅
one    → t·f 없음 ❌
```

**`tf` 와 다른 점:** `two` 에는 `t`만 있고 **`tf` 연속은 없음** → 매칭 **0줄**.

**비슷한 것:** `grep -e t -e f` · `grep '[tf]'` (`2-13`) — OR 느낌이지만 **`[tf]` 는 “한 글자”** 조건.

### 1-13
**문제:** `tar -tf` 는 아카이브 **목록만** 보고, **추출하지 않는다**. ( O / X )

**정답:** **O**

**해설 — `tar -tf` 옵션 (`2-19`와 같음):**

**`tar`** = **t**ape **ar**chive (파일 묶음).

```bash
tar -tf test.tar
#    ││
#    │└ -f = **f**ile (뒤에 **아카이브 파일 이름**)
#    └── -t = **t**able of contents / lis**t** (목록만 **보기**)
```

| 옵션 | 축약 뜻 | 역할 |
|------|---------|------|
| **`-t`** | lis**t** | 아카이브 **안 파일 이름만** 출력 · **추출 안 함** |
| **`-f`** | **f**ile | **어떤 `.tar` 파일**인지 지정 (`test.tar`) |
| **`-x`** | e**x**tract | 아카이브 **풀기(추출)** (`2-20`) |
| **`-v`** | **v**erbose | 처리하는 **파일 이름을 화면에 출력** (`2-18` `cvf`) |

**비교:**

| 명령 | 하는 일 |
|------|---------|
| **`tar -tf test.tar`** | 안에 뭐 있는지 **목록만** (이 문제 · **O**) |
| **`tar -xf test.tar`** | **조용히** 추출 (`v` 없음) |
| **`tar -xvf test.tar`** | 추출 + **꺼내는 파일 이름** 출력 (`v` = verbose) |

→ **`-t`** = 보기만 · **`-x`** = 꺼내기 · **`-v`** = 진행 **출력** · **`-f`** = tar 파일 이름.

### 1-17 (`df -h | grep '/$'` · 루트 파티션)
**상황:** `df -h` = 디스크 **여유 공간** (`-h` = **human-readable** · `100G` 등) · **Mounted on** = 어디에 **붙었는지**(마운트 경로).

```
Filesystem      Size  Used Avail Use% Mounted on
/dev/sda1       100G  40G  55G  43% /
/dev/sdb1        16G   4G  12G  25% /media/disk
tmpfs           3.2G  2.2M  3.2G   1% /run
```

**문제:** `df -h | grep '/$'` 는 **Mounted on 이 `/` 인 줄**(루트 파티션)만 고른다. ( O / X )

**정답:** **O**

**해설 — `df -h` 와 `grep '/$'`:**

```bash
df -h | grep '/$'
#  ↑       ↑↑
#  h       / = 루트 "/"
#  human      $ = 줄 끝
```

| 부분 | 축약 | 역할 |
|------|------|------|
| **`df`** | **d**isk **f**ree | 파일시스템 **여유·사용 공간** (`1-5`) |
| **`-h`** | **h**uman-readable | `100G` `55G` 처럼 **G·M 단위**로 표시 (`2-9` · `-h` 없으면 블록 수 등 **읽기 어려운 숫자**) |
| **`/`** (grep) | 루트 경로 | **Mounted on** 이 `/` 인 줄 찾기 |
| **`$`** (grep) | 줄 **끝** | `/` **뒤에 글자 없음** ( `/media` `/run` 제외) |

**왜 `$` 가 필요?**

| 줄 끝 | `grep '/$'` |
|-------|-------------|
| `… 43% **`/`**` | **매칭** (루트 파티션) |
| `… 25% **`/media/disk`**` | **안 됨** (`/` 뒤에 `media` 가 더 있음) |
| `…  1% **`/run`**` | **안 됨** (`/` 뒤에 `run`) |

→ **`/$`** = “줄이 **`/` 로 끝난다**” = **Mounted on 이 `/` 인 줄만** (`5-3`).

**이 명령 결과 (예):**

```
/dev/sda1  100G  40G  55G  43% /
```

### 1-19 (`tar -cvzf` · gzip tar **만들기**)
**상황:** `history 4.sh` · 현재 폴더 **전체**를 **압축 tar** 로 저장:

```bash
tar -cvzf archiv.tar.gz *
```

**문제:** `tar -cvzf` 의 **`-z`** 는 **gzip 압축**을 의미한다. ( O / X )

**정답:** **O**

**해설 — `c` `v` `z` `f` 각각:**

| 옵션 | 축약 | 역할 |
|------|------|------|
| **`-c`** | **c**reate | **새 tar 아카이브 만들기** (`2-18`) |
| **`-v`** | **v**erbose | 넣는 **파일 이름 출력** (`1-13`) |
| **`-z`** | g**z**ip | **gzip으로 압축** (`.tar.gz` · `2-21`) |
| **`-f`** | **f**ile | **만들 파일 이름** (`archiv.tar.gz`) |

```bash
tar -cvzf archiv.tar.gz *
#    │││└ -f → archiv.tar.gz
#    ││└─ -z → gzip 압축
#    │└── -v → 진행 출력
#    └─── -c → 생성
```

**비교 (`1-13`):**

| 명령 | 하는 일 |
|------|---------|
| **`tar -cvzf a.tar.gz *`** | **만들기** + gzip (`c` + `z`) |
| **`tar -zxvf a.tgz`** | **풀기** + gzip (`x` + `z` · `2-20`) |
| **`tar -tf a.tar`** | **목록만** (`t` · 압축 없는 tar) |

→ 이 문제는 **`-z` = gzip** 만 **O/X** 로 묻지만 · 네 글자는 **create + verbose + gzip + file**.

### 1-20 (`history 5.sh` 주석 vs `Lecture/file2`)
**상황:** `sort file2` 설명용 **`history 5.sh` 주석** 과 **실제 파일**이 **다름**.

**`history 5.sh` 28~32행 (주석·슬라이드용 예시):**

```bash
sort file2 ( 숫자순 정렬 )
# 1, 100 ,2 20          ← sort 기본(사전순) 결과 **예시**
sort -n ( Numeric )
# 1, 2, 10, 20          ← sort -n 결과 **예시**
```

| `sort` | 결과 순서 |
|--------|-----------|
| **(없음)** | 사전순 (`100K` · `1.2M` · `4.0K` — **크기순 아님**) |
| **`-h`** | 작은→큰 (`4.0K` → `100K` → `1.2M`) |
| **`-hr`** | **큰→작은** (`1.2M` → `100K` → `4.0K`) ← 이 문제 |

| 명령 | 해석 | 결과 |

| **`grep t f file1`** (X) | `t`=패턴 · **`f`=파일 이름** · `file1`=??? | **문법/의도 틀림** |
| **`grep -e t -e f file1`** (O) | `t` **또는** `f` 포함 줄 | `two` `three` `four` `five` |
| **`grep '[tf]' file1`** | 같은 의미 (한 글자 t 또는 f) | 위와 같음 (`history 5.sh` 41~42행) |

→ **`-e` 두 번** = “패턴 두 개” · **`egrep` 아님**.

| 명령 | 같은 것 | 패턴 해석 | 예 |
|------|---------|-----------|-----|
| **`grep`** | (기본) | **기본** 정규식 · `.` = 임의 한 글자 | `grep "." file3` → 내용 있는 줄 **전부** |
| **`egrep`** | **`grep -E`** | **확장** 정규식 · `\|` `()` 등 | `egrep 'init\|bash'` (`1-10`과 다름) |
| **`fgrep`** | **`grep -F`** | **고정** 문자열만 · 메타문자 **안 씀** | `fgrep "." file3` → **점(.)** 있는 줄만 |

| | **이 문제 `-e`** | **egrep (`-E`)** |
|--|------------------|------------------|
| 뜻 | 패턴 **여러 개 나열** (OR) | **확장 정규식** 문법 |
| 예 | `grep -e t -e f` | `egrep 'tw\|fo'` |

### 2-14
**상황:** 파일에서 **빈 줄 제외**.

```bash
grep -v '______' file_name
```

**정답:** `^$`

**해설:** `^` = 줄 맨 앞 · `$` = 줄 맨 끝 → 사이 글자 없음 = 빈 줄.

**따옴표 (`'` vs `"`):**

| 작성 | 동작 |
|------|------|
| `grep -v '^$' file` | ✅ |
| `grep -v "^$" file` | ✅ (`^$` 에서 `$` 뒤에 변수명 없음 → **그대로** grep에 전달) |

→ **`^$` 는 작은따옴표·큰따옴표 둘 다 OK.** 문제의 `'` 는 “패턴을 한 덩어리로 넘긴다”는 예시일 뿐, **`^$` 가 작은따옴표만 써야 한다는 뜻 아님.**

**왜 보통 `'` 를 쓰나:** 정규식에 `$변수`, `` ` `` 등이 있으면 `"` 안에서 **쉘이 해석**할 수 있음. 그래서 regex는 **`'`(리터럴 고정)** 이 더 안전.

```bash
grep -v '^$' file_name    # 빈 줄 제외 (권장)
grep -v "^$" file_name    # 이 패턴은 결과 동일
```

### 2-15
**상황:** **현재 디렉터리 이하 전체**에서 `two` 검색 (`history 5.sh`).

```bash
grep -R "______" .
```

**정답:** `.*two` (전체: `grep -R ".*two" .`)

**해설 — `.` 가 **두 군데** 있지만 **역할이 다름** (`history 5.sh` 47행):**

```bash
grep  -R   ".*two"   .
│     │      │       └── ② 마지막 .  (따옴표 밖)
│     │      └── ① 따옴표 안 패턴
│     └── -R = Recursive (하위 폴더까지)
└── grep
```

| 위치 | 쓰임 | 뜻 |
|------|------|-----|
| **① `".*two"` 안의 `.`** | **정규식** | **아무 글자 1개** · `*` 와 합쳐 **`.*`** = 앞에 아무 문자열이나 와도 됨 |
| **② 맨 끝 `.`** | **경로(파일명)** | **현재 디렉터리** (`ls .` 의 `.` 와 같음) · **정규식 아님** |

→ 헷갈리기 쉬운 점: **따옴표 안 `.`** = 패턴 · **따옴표 밖 `.`** = “여기서부터 검색해”.

**② 마지막 `.` 이 하는 일:**

- grep에게 **“어디를 뒤질지”** 알려 주는 인자 (패턴이 아님).
- **`.`** = 지금 있는 폴더 · **`-R`** 과 함께 쓰면 **그 폴더 + 하위 폴더 전부** 검색.
- `file1` 처럼 **파일 이름**을 쓸 수도 있음 → 범위가 그 파일로만 좁아짐.

| 명령 | 마지막 인자 | 범위 | `Lecture/` 예 |
|------|-------------|------|----------------|
| `grep "two" file1` | `file1` (파일) | **그 파일만** | `two` |
| `grep "two" .` | `.` (폴더) · **`-R` 없음** | 디렉터리 직접 읽기 불가 | `Is a directory` |
| `grep -R ".*two" .` | `.` (폴더) · **`-R` 있음** | **현재 폴더 이하 전체** | `./file1:two` 등 |

**① 패턴 `.*two` 요약:**

- **`.*`** + **`two`** = “앞에 뭐가 있어도 **`two` 포함** 줄”.
- `*` 는 **`two` 앞의 `.`** 에 붙음 (`two*` ❌ = `tw`+`o`반복).
- `two` **뒤**는 굳이 `.*` 안 씀 — grep이 줄 어디서든 `two` 를 찾음.

```bash
grep -R ".*two" .     # ① two 패턴  +  ② 현재 폴더 이하 검색
grep -R "two" file1   # ① two 패턴  +  ② file1 만
```

**상황:** **`filename.tgz`** (gzip tar) **현재 디렉터리에 풀기** (verbose).

```bash

```

**정답:** `zxvf`

**해설 — `zxvf` = gzip 해제 + tar 풀기 **한 번에** (`1-19` · `3-3`):**

| 옵션 | 역할 |
|------|------|
| **`z`** | **gzip 압축 해제** (`.tgz` / `.tar.gz` 바깥 껍질 풀기) |
| **`x`** | tar **추출** (안에 묶인 파일·폴더를 현재 디렉터리에 풀기) |
| **`v`** | 풀리는 **파일 이름 출력** |
| **`f`** | 대상 파일 **`filename.tgz`** 지정 |

**`.tgz` 안에 뭐가 있나:**

```
filename.tgz  =  [ gzip으로 압축된 tar 묶음 ]
                  └─ tar 안에 file1, file2, …
```

→ **`tar -zxvf filename.tgz` 한 줄**이면 **gzip 해제 → tar 풀기**까지 끝. **`gunzip` 따로 안 써도 됨.**

| 명령 | gzip | tar 풀기 |
|------|------|----------|
| **`tar -zxvf filename.tgz`** ✅ | **`-z` 가 함께** | **`-x`** |
| **`tar -xvf filename.tgz`** ❌ | 안 함 | `.tgz`는 압축 상태라 **실패/깨짐** |
| **`gunzip` 후 `tar -xvf`** | 따로 2단계 | 가능하지만 수업은 **`-z` 한 번** |

```bash
tar -zxvf filename.tgz    # 현재 폴더에 원본 파일들 복원 (+ v 로 이름 출력)
```

**만들 때와 짝:** `tar -cvzf` = 묶기 + gzip (`2-21`) · `tar -zxvf` = gzip 풀기 + 꺼내기.

### 2-28 (`mount -o` 옵션)

|------|------|------|

**참고 — `check=none` (무결성 검사 생략):**

| 항목 | 내용 |
|------|------|
| **무결성 검사** | **마운트할 때** ext2 등 파일시스템 **내부가 깨지지 않았는지** 빠르게 확인 (슈퍼블록·비트맵 등 **서로 맞는지** 점검) |
| **`check=none`** | 위 검사를 **마운트 시점에 하지 않음** (`nocheck` 와 같음) |
| **언제 생략?** | `-o check=none` 을 쓸 때 · 사실 **기본값이 none** 이라 **보통 마운트만 하면 검사 안 함** (빠르게 붙이기) |
| **언제 검사?** | **부팅 시 `fsck`/`e2fsck`** 처럼 **별도로** 돌릴 때 (마운트 옵션과 다른 단계) |

```bash
mount -o check=none /dev/sdb1 /media/disk   # 마운트 시 내부 점검 생략 (기본과 비슷)
mount -o ro,check=none /dev/sdb1 /media/disk # ro 와 함께 쓸 수 있음
```

**해설 — 세 줄 역할 (`history 4.sh` 5~6행):**

| 줄 | 옵션 | 하는 일 |
|----|------|---------|
| 1 | **`cvzf`** | **만들기** (`c`) + verbose (`v`) + gzip (`z`) + 파일 (`f`) |

**옵션 글자 순서 — 바꿔도 되나?**

| 규칙 | 설명 |
|------|------|
| **`c` `v` `z` `x` `t` 끼리** | **순서 자유** · `cvzf` = `zcvf` = `zvcf` (**동일**) |
| **`f` 는 묶음에서 맨 끝** | **`-f` 뒤에 아카이브 파일명**이 와야 함 → **`-cvzf archiv.tar.gz`** 처럼 **`f`를 마지막**에 두는 게 **수업·시험 표준** (`4-2`: `xvzf` = `zxvf`) |
| **`f` 가 끝이 아니면** | **`-cvfz`**, **`-xvfz`** 등 → `f` 가 **다음 글자(`z`)를 파일명**으로 착각 · **오류/오동작** |

```bash
tar -cvzf archiv.tar.gz *   # ✅ (수업 정답)
tar -zcvf archiv.tar.gz *   # ✅ 순서만 바뀜
tar -cvfz archiv.tar.gz *   # ❌ f 가 끝이 아님
tar -tf archiv.tar.gz       # ✅ 목록
tar -ft archiv.tar.gz       # ❌
```

→ **글자 순서는 대체로 바꿔도 되지만 · `f`는 항상 옵션 묶음의 맨 마지막.**

### 3-5
**상황:** Shell 변수 설정·출력·수정 (`history 5.sh`).

```bash
test=testing
______ $test
test='testing a b c'
test=$test:.
```

**정답:** `echo` · 마지막 `$test` 값 = **`testing a b c:.`**

**해설 — 줄별 (`history 5.sh` 63~79행):**

| 줄 | 의미 |
|----|------|
| `test=testing` | 변수 `test` 에 `testing` 저장 |
| **`echo $test`** | 변수 **출력** (빈칸 = `echo`) |
| `test='testing a b c'` | 값 **통째로** 바꿈 (공백 포함) |
| `test=$test:.` | **기존 값 + `:.`** 로 **이어 붙이기** → `testing a b c:.` |

**`$test:.` vs `$test" four five"` — 같은 원리?**

**큰 틀에서는 같음:** `$test` **펼친 값 + 뒤에 이어 쓴 글자**가 **한 덩어리(한 word)** 로 이어 붙음.

**하지만 “특수기호 = 글자 하나”가 아님 · `$testabc` 는 `test`+`abc` 가 아님.**

쉘은 `$` 뒤 **변수 이름을 어디까지인지** 먼저 판단함:

| 작성 | 쉘이 보는 변수 | 결과 (`test=hello` 일 때) |
|------|----------------|---------------------------|
| **`$testabc`** | **`testabc`** (이름이 더 길게 이어짐) | `testabc` 변수 찾음 → **없으면 빈 값** · `hello`+`abc` **아님** |
| **`$test:.`** | **`test`** 까지 · `:` 는 이름에 **못 들어감** | `hello` + `:.` → **`hello:.`** |
| **`${test}abc`** | **`test`** (중괄호로 이름 **끊기**) | `hello` + `abc` → **`helloabc`** |
| **`$test"abc"`** | **`test`** · 바로 뒤 `"` 가 이름 **끊김** | `hello` + `abc` → **`helloabc`** |

→ **`test=$testabc` 로 `abc`를 붙이는 게 아님** — 이전 해설 예시는 **틀림**. 글자·숫자가 변수명에 이어지면 **한 이름**으로 읽음.

**이 문제 `test=$test:.` 가 되는 이유:**

- `$test` 까지 변수 · **`:`** 는 변수 이름 문자가 **아니라서** 여기서 이름 **종료**
- 그 뒤 **`.`** 포함 `:.` 가 **글자 그대로** 붙음

| 작성 | 붙는 것 | 왜 |
|------|---------|-----|
| **`test=$test:.`** | `:` + `.` **두 글자** | `:` 가 변수명 종료 → 이어 붙기 |
| **`test=$test" four five"`** | ` four five` | `"` 가 변수명 종료 + **공백**을 한 덩어리로 묶음 |

**뒤에 글자를 붙이는 올바른 방법:**

```bash
test=$test:.              # : 가 이름 끝 → OK (수업)
test=${test}abc           # 중괄호로 이름 끊고 abc 붙이기
test=$test"abc"           # 따옴표로 이름 끊고 abc 붙이기
test=$testabc             # ❌ testabc 라는 다른 변수 (의도와 다름)
```

**변수 이름에 `:.` 같은 특수기호가 들어가면?**

→ **변수 이름에는 특수기호를 쓸 수 없음.** (`test:.` 같은 이름 **불가**)

| 규칙 | 허용 | 불가 예 |
|------|------|---------|
| **첫 글자** | 영문 · `_` | `1test` · `-test` |
| **이후 글자** | 영문 · 숫자 · `_` | **`:` `.` `-` 공백** 등 |

```bash
test=hello          # ✅ 변수 이름 test
_test123=ok         # ✅
test:.=hello        # ❌ 변수 이름이 test:. 가 아님 → 명령으로 해석·오류
test.abc=hello      # ❌
test-abc=hello      # ❌
```

**`test=$test:.` 에서 `:.` 의 위치:**

- **`test`** = 변수 **이름**
- **`=`** 뒤 **`$test:.`** = **값**을 만드는 식 (이름 `test` + 붙는 글자 `:.`)
- `:.` 는 **이름 일부가 아니라 값에 덧붙는 문자**

**정리:** 변수 **이름** = `a`~`z`, `A`~`Z`, `0`~`9`, `_` 만 · **`:.` 는 값에 붙는 것** · 이름에 특수기호 넣으려면 **`test_dot`** 처럼 **이름을 바꿔야** 함.

| **`df`** | **d**isk **f**ree | 파일시스템 **용량·여유 공간** 표 |
| **`-h`** | **h**uman-readable | `16G` `4G` `12G` 처럼 **읽기 쉬운 단위** (G·M·K) |

**`-h` 없으면** `906007372` 같은 **1K-blocks** 숫자 → **`-h` 있으면** `865G` 처럼 보기 쉬움.  
→ 이 문제 정답(`/media/disk`)에는 **`-h` 유무와 무관** · **Mounted on** 열만 보면 됨.

| 열 | 이 줄에서 |
|----|-----------|
| **Filesystem** | `/dev/sdb1` (장치) |
| **Size / Used / Avail / Use%** | 용량 (`-h` 덕분에 G 단위) |
| **Mounted on** | **`/media/disk`** ← 마운트 포인트 (정답) |

### 5-3
**상황:** `df -h` 출력 한 줄.

```
/dev/sda1  100G  40G  55G  43% /
```

**문제:** `55G` 열의 의미는? `43%`는?

**정답:** `55G` = **Avail**(사용 가능 여유) · `43%` = **Use%**(사용률)

**해설 — `df -h` 한 줄 **전체 열** (`1-17` 헤더와 대응):**

```
Filesystem   Size  Used Avail Use% Mounted on     ← 헤더 (문제는 생략)
/dev/sda1    100G  40G  55G  43%  /
```

| 순서 | 값 | 열 이름 | 뜻 |
|------|-----|---------|-----|
| 1 | **`/dev/sda1`** | **Filesystem** | **어느 장치·파티션**인지 (블록 장치) |
| 2 | **`100G`** | **Size** | 그 파일시스템 **전체 용량** |
| 3 | **`40G`** | **Used** | **이미 쓴** 용량 |
| 4 | **`55G`** | **Avail** | **지금 더 쓸 수 있는** 여유 (일반 사용자 기준) |
| 5 | **`43%`** | **Use%** | **사용률** = Used ÷ Size 비율 |
| 6 | **`/`** | **Mounted on** | 디스크가 트리 **어디에 붙었는지** (마운트 포인트 · `5-2`) |

**`-h`:** 위 용량(`100G` 등)을 **G·M 단위**로 읽기 쉽게 표시 (`5-2`).

**참고:** `40G` + `55G` = `95G` ≠ `100G` 인 경우 있음 — 일부는 **시스템 예약** 등으로 **Avail에 안 잡힘** (시험은 **열 이름**만 알면 됨).

**문제:** (1) `du ~` (2) `du -sh ~` 출력 **형태** 차이를 한 줄씩?

**해설 — `~` 와 옵션:**

| 기호/옵션 | 뜻 |
|-----------|-----|
| **`~`** | **홈 디렉터리** (tilde) · 쉘이 **`/home/사용자명`** 등으로 **펼침** (예: `~` → `/home/sj`) |


### 6-1
**상황:** `Lecture/file1`

```

```

**문제:** `grep t file1` 출력 줄? (순서대로)

**정답:**

```

```

**해설:** `t` **포함** 줄만 · `two` / `three`.

**`grep t file1` — 따옴표 없어도 되나?**

→ **단순 패턴 `t` 는 따옴표 없어도 됨** (`history 5.sh` 38행도 `grep t file1`).

| 작성 | 결과 (`file1`) |
|------|----------------|
| **`grep t file1`** | `two` / `three` |
| **`grep 't' file1`** | **동일** |
| **`grep "t" file1`** | **동일** |

**따옴표 — 쉘 vs grep (헷갈리기 쉬운 점):**

**두 단계**로 나뉨:

```
명령 입력 → [① 쉘이 해석] → grep 에 전달 → [② grep 이 정규식 해석]
```

| 단계 | 누가 | 예 |
|------|------|-----|
| **① 쉘** | `|`, `$`, `*`, 공백 등 **쉘 특수문자** 처리 | `\| ` 없이 `\|` = **파이프** (다른 명령 연결) |
| **② grep** | `.`, `[]`, `^`, `$` 등 **정규식** 처리 | `[tf]` = t 또는 f **한 글자** (`1-11`) |

**작은따옴표 `'` 의 역할 = ①만 막음:**

- **`'` 안** → 쉘이 **아무것도 해석 안 함** · `$` 도 변수 **안 펼침** · `|` 도 **파이프 아님** → **글자 그대로** grep에 전달.
- **grep이 받은 뒤** `|` 가 OR 인지 `|` 글자인지는 **grep/egrep 규칙** (`1-10`):
  - `grep 'tw|fo'` → 쉘은 `|` 를 파이프로 **안 씀** · grep 기본에서는 `\|` 가 OR
  - `egrep 'tw|fo'` → grep 쪽에서 `|` = **OR**

→ **작은따옴표 = “쉘한테 손대지 마”** · **정규식 의미는 grep이 결정** (`$` 만이 아님).

**언제 따옴표가 필요? (① 쉘 때문에)**

| 패턴 | 안 쓰면 | `'` 쓰면 |
|------|---------|----------|
| **공백** (`two three`) | word 쪼개짐 | 한 패턴으로 전달 |
| **`|`** (`tw\|fo`) | **파이프**로 오해 | `\|` 글자 그대로 grep에 전달 |
| **`$`** (`^$`) | 큰따옴표면 변수 확장 위험 | 리터럴 `^$` 전달 (`2-14`) |

**`t` 만:** ①② 모두 특별할 것 없음 → **`grep t file1` = `grep 't' file1`** OK.
